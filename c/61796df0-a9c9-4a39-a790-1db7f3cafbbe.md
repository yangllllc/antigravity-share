#### 2.1 审计 #9（负反馈 ID 复用误拦、无序指纹失真、审阅对比与锁内重查）

**拟定最小改动（涉及 `governance.py`、`review_ui.py`）**：
1. **永久单调 ID + 移除裸 `entry_id` 一票否决**：
   - 删除 `check_feedback_collision` 中 `blocked_entry_id` 分支（旧账本 `entry_id` 仅作历史溯源，不封禁未来新项）。
   - `_next_entry_id(prefix, used_ids)` 改为取匹配 `^{prefix}-(\d+)$` 的 `max + 1`（不再填空洞）；`stage_proposal` 的 `used_ids` 合并同 `(tier, topic)` 下现存条目 + 历史账本记录 + 同批已分配 ID，确保已拒/已撤编号不再复分配。

   - `normalize_text_ordered(text)` 做 NFKC 规范化、小写化、标点转单空格、折叠空白（保留全部单字如 `不/勿/非/仅` 及英文短词 `no/not` 与词序）。

3. **近似命中（`semantic_token_overlap`）降误报 + 审阅页并列展示**：

#### 2.2 审计 #12（多行结论静默截断及连带破坏 CAS Revert）

**核心矛盾**：`store.py` 允许 `claim` 原样换行输出，但 `_parse_entry_block`（`L113-L128`）只读取 `- **结论**:` 首行并静默丢弃后续行；这不仅在下一次重渲染时永久删除限制条件，还会导致刚批准的多行条目触发 `revert_item` 的 CAS 冲突失败；另外 `governance.py` 把 `prev_claim[:80]` 直接塞进 `changelog`，多行时会连带截断溯源行。

**拟定最小改动（涉及 `store.py`、`governance.py`、`review_ui.py`）**：
1. **Tier 3 支持 2 空格缩进续行 + 兼容读取既有多行**：
   - `MemoryEntry.render()`：单行 `claim` 保持原样（与现有生产 17 条逐字节一致）；多行 `claim` 首行 `- **结论**: <line0>`，后续每行渲染为 `"  " + line_i`。
   - `_parse_entry_block()`：新增 `in_claim` 状态，遇到 `- **结论**:` 后持续吸收后续行（规范 2 空格缩进剥离前 2 空格；历史未缩进多行兼容保留），直至遇到 `- **替代旧条目**:` / `- **变更溯源**:` / `### ` 结束。
2. **结构安全与单行字段硬校验**：
   - `stage_proposal` 强制拒绝：`title`、`change_note`、`topic_title`、`topic_summary` 以及 **Tier 1 `promoted_rule` 的 `claim`**（防破坏 `AGENTS.md` 列表与行预算）含 `\r`/`\n`；并拒绝任意 `claim` 内含 `<!-- ENTRY_START` / `<!-- ENTRY_END` 或顶格 `- **结论**:` / `- **变更溯源**:` / `- **替代旧条目**:` / `### ` 等结构边界标记。
   - `governance.py:233` 的 `[旧结论: ...]` 改为 `" ".join(prev_claim.splitlines())[:80]`，杜绝换行污染 `changelog`。
   - `review_ui.py` 为主张展示区补 `white-space: pre-wrap`，确保审阅页直观呈现多行。
3. **代码级往返不变量断言**：
   - 在 `store.py` 新增 `assert_entry_roundtrip(entry)`（验证 `parse_topic_text(entry.render())` 完整保留 `title`、`claim`、`changelog`），在 `stage_proposal` 与 `apply_decisions` 写盘前均执行校验；`_fit_lines_within_budget` 同步按真实换行符计行兜底。
