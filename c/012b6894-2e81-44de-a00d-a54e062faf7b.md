## 一、用大白话讲透：这套记忆系统到底是怎么运转的？

你可以把它理解成**“大脑白天的聊天记录 → 晚上按需整理成笔记本 → 贴一张精简目录在桌面上”**的三层结构：

```text
[你每天的 Antigravity 对话] (底层明文 transcript.jsonl + summaries.db)
        │
        ▼ ① Python 脚本（隔离拷贝、跳过已归档/子代理、脱敏密钥、砍掉超长工具日志）
[干净的增量对话批次 batch_*.md]
        │
        ▼ ② Antigravity 强模型读批次 + 读旧索引 + 读你过去的驳回记录
[精简变更提案 proposal.json]（只说“新增/覆写/废弃哪几条”，绝不乱改原文件）
        │
        ▼ ③ Python 脚本验预算、查泄露、撞负反馈账本、算 Diff、渲染审阅页
[人工审阅闸门]（聊天直接批复 / 浏览器 review.html 一键确认）
        │
        ▼ ④ 自动建只读快照 → 原子写入 → 确定性重新编译桌面目录
┌──────────────────────────────────────────────────────────┐
│ Tier 0（绝不碰）：你手写的 core-reasoning-protocol.md / CONTEXT_*.md │
│ Tier 1 + Tier 2（自动编译到插件 rules/AGENTS.md，每次对话常驻，硬顶≤12KB）│
│   ├─ Tier 1：经你点头晋升的极少数“全局铁律”                          │
│   └─ Tier 2：一张极短的“主题目录表”（只写每个主题管啥、存在哪）          │
│ Tier 3（plugin_data/.../topics/*.md，平时不占上下文，聊到相关领域才读） │
└──────────────────────────────────────────────────────────┘
```

### 为什么这样设计？（核心好处）
1. **贴合 Antigravity 原生机制，零常驻负担**：因为它是原生插件 `antigravity-dream-memory`，Antigravity 会自动在每次新对话加载它的 `AGENTS.md`（只是一张很轻的目录 + 极少数晋升规则，占不到 1.5 KB），而详细的踩坑经验全藏在 `topics/*.md` 里，**聊光路才读光路、做 PPT 才读 PPT**，不会越用越臃肿。
2. **能“改错”而不是“只增不减”**：传统向量记忆库（RAG）只会越塞越多，新旧结论打架全靠碰运气；这套系统每次整理都对照旧条目，发现新结论推翻了旧结论时直接原地覆写并留一行“旧结论溯源”。
3. **重体力活全交脚本，防 60 秒断连、防误删、防死循环**：
   - 脚本按每个会话记录“读到第几步 + 锚点哈希”，下次只抽新增发言；
   - 写盘前一定先锁死一份只读时间戳快照，随时能单条 `revert` 或整批 `rollback`；
   - 你只要驳回或撤回某条记忆，原因就会写进 `feedback_ledger.jsonl`，以后哪怕模型换个说法重新提议，也会被指纹+中文词袋重合检测直接拦下来。

### 实话实说：这套方案有哪些缺点和不足？
1. **不是实时记忆，靠你主动 `/dream` 触发**：刚聊完的新偏好在下次跑 `/dream` 前不会自动进全局记忆（优点是干净可控、不卡顿，代价是需要偶尔手动触发一次，如每周一次）。
2. **Tier 3 的“按需读取”依赖模型自觉查目录**：虽然目录表每次都会注入上下文，但如果用户在某次对话问法非常隐晦、没命中目录里的关键词，模型偶尔可能忘了主动去 `read_file` 对应的 `topics/*.md`（相比向量库自动召回，这里用“完全透明可审计”换取了少量“隐式召回率”）。
3. **纯规则/词袋防复提的边界**：`feedback_ledger.jsonl` 目前能拦住原话和较高字面重合的同义改写；但如果模型彻底换了一套完全不同字眼的说法，主要靠提示词层的语义遵守，脚本层无法 100% 硬拦。
4. **本次实测刚抓出一个小瑕疵**：在读你 `Optics Grilling Tutor Session`（`c9eb2bf0`）的真实记录时，我发现 Antigravity 在你编辑重发同一条消息时，会在 `transcript.jsonl` 里留下多条相同 `step_index` 的旧草稿（如 `step=11` 出现了 4 次）。目前不影响强模型读懂，但会多耗一点批次字数，后续在 `extractor.py` 加 5 行按 `step_index` 保留最后一条的去重即可消除。
5. **对你“默认跳过已归档、纳入日常对话”想法的客观评估**：你的直觉整体是对的——日常对话确实最能反映你的表达习惯和真实诉求。唯一风险是**把阶段性情绪或一时决定误固化成永久规则**；靠“反死板提炼（只留持久习惯）+ Tier 3/Tier 1 分级 + 你审阅兜底”可以把这个风险压到很低。另据实机核查，你目前 `annotations/` 中标记 `archived:true` 的会话数是 **0 条**（哪怕标题叫 `已过期1` 的也没点过归档），今后凡是在左侧栏或归档插件里归档过的对话都会自动跳过。

## 2. 核心架构选型、权衡与红队加固

本次核心矛盾在于：**既要让强模型自由做跨会话语义归并、冲突覆写与边界判断，又要防止大输出触发约 60 秒网关断连、防止记忆膨胀撑爆常驻上下文、防止错误规则静默生效或反复回流。**

1. **增量读取与水位线（`extractor.py`、`redact.py`）**
   - **选型**：隔离临时目录拷贝 SQLite（含 `-wal`/`-shm`）+ `PRAGMA quick_check` 重试后只读打开；按 `conversation_id` 独立维护 `{last_step_index, anchor_step_hash, compact_sig, full_sig}` 水位线；老对话续写自动附带前 1 轮 `[CONTEXT_ONLY]` 上下文，若文件截断或锚点行 SHA-256 漂移则自动全量重放。4 层防自污染（过滤 `nesting_depth>0` 子代理、哨兵标记与 `/dream` 识别、`--exclude-cid`、turn 级切片过滤）+ 13 类正则凭据脱敏 + 剥离 `GENERIC` 大输出 + 超长会话按轮次切分保证每批 ≤ 18,000 字符。
   - **否决**：单一全局时间戳水位线（无法正确处理老对话续写）；直接只读打开 live SQLite（存在 Windows 锁冲突风险）；逆向 Protobuf（高脆弱且多余）。
2. **原生形态与三层 SSOT（`store.py`、`plugin.json`、`SKILL.md`）**
   - **选型**：Antigravity 原生 Plugin 结构（一键启停、与原生全局规则物理隔离）。Tier 0（用户 `config/rules/*.md` 与 `CONTEXT_*.md`）代码级路径硬锁禁止触碰（`config_io.py`）；Tier 1（`promoted_rules.md`）与 Tier 3（`topics/<slug>.md`，单文件 ≤ 150 行）为单一事实源（SSOT）；Tier 2 索引（`INDEX.md`）和常驻规则产物 `AGENTS.md` 100% 由脚本确定性编译，同时受 **≤ 140 行且 ≤ 12,000 UTF-8 字节**约束（按行边界字节安全截断，杜绝截断中文多字节字符，溢出项自动降级为 `topics/` 目录指针）。
   - **否决**：自定义 MCP Server（常驻开销与全会话 schema token 税）；手写维护双份索引/规则文件（必然漂移）。
3. **分析编排与防超时（`SKILL.md`）**
   - **选型**：脚本承担全部确定性 I/O、清洗、校验、Diff、快照与原子写盘；模型只输出紧凑结构化 `proposal.json`（避免整文件重写触发 60 秒断连）。自适应路由：`batches <= 2` 主模型直出，`batches > 2` 按每 2 批派发原生只读 `research` subagent（`Model="inherit"`）抽取后再由主模型统一去重和冲突裁决，**零外部 API/MCP**。
   - **否决**：每次强制拉起 Swarm/多代理（小增量浪费配额）；模型直接手写全量 Markdown/HTML。
4. **人工审阅、原子写盘与负反馈闭环（`governance.py`、`review_ui.py`）**
   - **选型**：三通道统一 `decisions.json` 契约——`review-serve` 加固本地服务（仅绑 `127.0.0.1:0`、校验 `Host`/`Origin` 防 DNS rebinding、256-bit CSRF nonce 一键应用）+ 离线双击 `review.html` 导出 JSON + 聊天内直接批复。写盘前必检 `base_hash` 漂移、加 PID 进程锁、生成只读（`0o444`）时间戳全量快照，同目录临时文件 `flush+fsync+os.replace` 重试，异常自动回滚。
   - **精准 Revert 与防改写绕过**：`revert` 按条目 ID（`MEM-XXXX`/`RULE-XXXX`）精准撤回，保留人工后续手工注释且不盲目回退水位线；驳回/撤回同时沉淀到 `feedback_ledger.jsonl`，在后续提示词层**和** `stage` 校验层（指纹 + 中英文 bigram 词袋重合度）双重阻断同义改写绕过。
   - **否决**：纯 Git Diff 手工改（难结构化沉淀驳回理由）；无校验裸开 localhost 服务。
5. **触发策略**
   - **选型**：默认手动 `/dream`；内置纯只读 `check-due` 子命令，生产启用后按需可选挂接轻量 `SessionStart` 提醒或 Antigravity 原生 `builtin: schedule` 定时预处理，永不静默改写 Tier 1。
   - **否决**：`Stop` Hook 每轮同步阻塞触发。
