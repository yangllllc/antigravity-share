### 一、 Gemini 报错 `URL_FETCH_STATUS_MISC_ERROR` 的真实根因

经 `curl.exe -sI` 实测公网地址 `.../c/8e491cda-d9db-4417-a196-9fe1a9a1b942.md` 与 `.../c/bb1e7994-b052-407c-8be9-f5c7c55e9456.md`：
- **并非 404 或 CDN 未分发**：早在 `10:01` 提交 `88e5533` 后，两个 `.md` 链接就已经返回 **`HTTP/1.1 200 OK`** 与 `Access-Control-Allow-Origin: *`。
- **真正阻塞点在 MIME 类型**：GitHub Pages 对 `.md` 返回的响应头是 **`Content-Type: text/markdown; charset=utf-8`**。部分云端网页抓取工具（如 Gemini 网页读取器）期望抓取 `text/html` 网页文档，遇到 `text/markdown` 会在底层直接拒收并报 `URL_FETCH_STATUS_MISC_ERROR`。
- 因此您提出的**一键下载 `.md` 文件后作为附件发给 AI**，正好同时绕开网页抓取器协议限制与 ~4,000 字符截断上限，是最可靠的分享方式。

### 二、 本步修改内容

1. **`template.html`**：
   - 将原顶栏的 `📄 纯净 .md` 与 `复制 AI 纯净版 (.md)` 合并为单个 **`⬇️ 下载 Markdown (.md)`** 按钮，并完整保留右侧 **`复制对话直链`** 按钮（复制对应 `.html` 永久分享链接）。
   - **下载逻辑双环境兼容**：
     - 在 `https://` / `http://` 访问时，使用 `fetch` + `Blob`（`text/markdown;charset=utf-8`）+ `URL.createObjectURL` 触发**强制下载**（避免浏览器只在新标签页打开预览而不保存文件），提供 `正在下载...` / `已下载 .md` 按钮状态反馈，异常时自动回退原生 `<a download>`。
     - 在本地 `file:///` 双击预览时，自动放行原生 `<a href="{{MD_HREF}}" download="{{MD_FILENAME}}">`，避免触发 `file://` 下 `fetch` 的 CORS 限制。

2. **`sync_share.ps1`**：
   - 新增 `Get-SafeDownloadName` 为 `{{MD_FILENAME}}` 生成易辨识且 Windows 安全的文件名（截取安全化标题 + 8 位会话短 ID，例如 `我想知道antigravity的对话该怎么分享，-bb1e7994.md`）。
   - 顺带修复了此前 `git` 命令用 `2>>$logFile` 重定向 stderr 导致 `sync.log` 混入 UTF-16LE 宽字符空格与正常推送提示的问题，改为捕获后按 UTF-8 仅在失败时记录详情。
