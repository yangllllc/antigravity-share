### 一、为什么感觉“修改完之后收集信息变慢了”？（实测：不是上次 Git 整理导致，而是 3 个叠加原因）

先澄清前提：上次整理 Git 只改了 `.gitignore` 和单测占位符，当前运行的 `AIRadar.exe` 仍是 `11-27 19:22` 的同一个包。**实测变慢来自抓取链路与 AI 审译链路两层叠加**：

1. **网络抓取墙钟耗时翻倍（实测：`12.1s → 24–25s`）**
   - 核查今天 `/api/runs` 历史：`08:32`（30 源）耗时 **24.0s**、`10:16`（30 源）耗时 **25.1s**。
   - **根因**：6 并发同时经本机代理 `http://127.0.0.1:12450` 拉取 19 个海外源时出现拥堵抖动，两轮分别有 **6 个 / 5 个海外源**撞上 `http.ts` 里 `connectSec = 5s` 的硬超时（`curl exit 28`）；外加 6 个 GitHub 源在 `collectors/index.ts` 共用单条串行泳道 `lane:github`（源内 700ms + 泳道 500ms 退让），仅 `github-ai-apps`（6.4s）与 `github-deepseek-releases`（5.5s）就拉长了长尾。
2. **体感“新消息出得慢/没翻译”的最大真相：上午配额已提前打光（实测）**
   - 今天 `11:36` 实测 `focusBudget` 已用 **`84/100`**，其中 **`tools`（55/55，余 0）** 与 **`community`（20/20，余 0）** 已经耗尽，导致当前「半小时精选」`25` 条里有 **`24` 条完全未审未译**（含 18 条 `tools` + 6 条 `community` 排队停住，以及本来就 `quota=0` 的时政/科技）。
   - 同时，22 项安全加固把旧版“边抓边无限并发跑 AI”改成了“全轮抓完 → `onCollectFinishedHook` 延迟触发 → 同济并发上限 `2`”，单条译文出现时机天然晚于整轮抓取，这是为了防同济 429 与超额的正常权衡。
3. **小细节（实测）**：今天 `09:24` 和 `11:32` 发生了两次进程重启，`11:32:59` 定时轮询仅抓取了到期的 5 个源（耗时 `2.1s`），并非卡顿没抓完。

**可做提速优化（零风险）**：海外源并发上限适当收紧（例如海外轨限 4 并发避免打爆本地代理端口）、将 `connectSec` 在有代理时放宽到 `7s` 减少假超时重试、把 `github-awesome-ai` / `github-selfhosted` 等低频静态清单拆出 `lane:github` 降低对热门新星的阻塞。

### 二、国内外时政为什么泛滥？——实测根因与“深度两级审核”方案

**实测数据触目惊心**：
- **总量第一且失控**：`politics` 活跃条目已达 **735 条（占全库 2040 条的 36.0%）**，构成：`cctv-news`（325）+ `rss-chinanews-china`（212）+ `rss-chinanews-world`（145）+ `rss-bbc-zh`（37）。
- **最近 100 条 100% 未审裸奔**：因为 `focusBudget.quotas.politics = 0`（关闭了时政 AI 审核），而前端默认 `hideRejected=1` **只隐藏 `ai_keep=0`、放行全部 `ai_keep IS NULL`**。
- **水新闻拿着高分霸占精选**：实测库内最新时政充斥《浙江金华：鹿女湖之晨》（**83 分**）、《安徽庐江：候鸟翩跹入画来》（**83 分**）、《“赣小橙”的兴农路》（**82 分**）、《日本发生野猪伤人事件致7伤》（**75 分**）、《阿根廷发生5.0级地震》（**83 分**），且因历史旧 Prompt 对央视过于宽松（`cctv-news` 曾审 124 条通过 116 条，通过率 `93.5%`），`score.ts` 给它打了虚高信任分，硬占「半小时精选」`6/25` 席位（`focus-selection.ts`）。

**建议的「L1 硬过滤 + L2 独立严审 + 未审零裸奔」两级漏斗**：
1. **L1 源头裁剪与规则硬闸（0 AI 成本先砍掉 ~80%）**
   - 裁剪 `cctv-news` 灌水子频道（仅保留主 `news` 或降单次上限）、`chinanews` 抓频降为 2 小时；
   - 新增时政专属噪音正则：直接拦截文旅风光/候鸟花草/农产品兴农/地方特产/动物伤人/一般社会治安/<6.5 级无重大伤亡地震/纯宣传套话；
   - **规则分封顶**：未通过 L2 严审的时政条目 `score` 上限压至 `≤ 58`，且不再用历史 `keepRate` 虚抬时政分。
2. **L2 专属严审 AI + 严格门禁（极省额度，不挤占 `tools/models`）**
   - 单独的时政审核口径：仅**国家级重大政策/立法/央行财政转向、大国元首外交与峰会、地缘冲突重大转折、重磅关税/芯片科技制裁与国际协议、重大突发公共事件**才判 `keep=true` 且给 `quality ≥ 4`；地方软新闻一律 `keep=false`。
   - **默认零裸奔门禁**：主屏与「半小时精选」只放行 `ai_keep = 1 AND ai_quality >= 4` 的重要时政（**未审 `NULL` 一律拦在归档里，不进主屏**）；半小时精选时政上限从 `6` 席降到 **`≤ 2` 席**（当天无重大事件可为 `0` 席，绝不凑数）。无 AI Key 时自动降级为“仅放行命中正向硬信号词的少量条目”，守住零成本红线。
   - **额度测算**：经 L1 筛完每天仅剩约 `15–25` 条候选，打包成每批 `10–15` 条只消耗 **1–2 次同济请求/天**（单独预算或少量划拨，几乎零感知）。
   - **存量 735 条清理**：先用 L1 规则批量把存量水新闻静默归档，仅对最近 24–48 小时过 L1 的少量候选跑一次 L2 严审，不浪费额度审旧闻。

### 三、按“点击 / 多次出现不点”动态分配 + 破格放行机制

**实测你的真实行为画像（库内已有 `12` 次点击 + `5` 条收藏）**：
- **高偏好**：GitHub 实战 AI/Agent/MCP 工具（`github-ai-apps` 3 击 1 藏、`github-ai-trending` 2 击、`github-mcp-tools` 1 击 1 藏）、国内极客实用贴（`rss-nodeloc` 4 击 2 藏）、单点高价值模型/思考（`rss-qbitai`、`rss-hnrss`）。
- **零点击重灾区**：`cctv-news` / `chinanews` / `bbc` / `hf-daily-papers` / `rss-infoq-cn` / `rss-solidot` 全部 **0 点击**。

**缺口**：目前数据库只记录了**点击/查看**（`last_viewed_at`/`view_count`）和**收藏**，没有记录**曝光次数（Impression）**，系统无法区分“你刷过 15 次都没点”和“刚入库你还没见过”。

**建议方案（v35 轻量个性化引擎，低写盘、防茧房、可一键恢复）**：
1. **防误记曝光埋点**：前端用 `IntersectionObserver` 仅当卡片可视面积 `≥ 60%` 且连续停留 `≥ 1.2s` 才算 1 次有效曝光（快速划过、后台标签页不计；同一条目每天最多计 1 次），每 10 秒/20 条合并批量上报后端聚合表，避免写爆 SQLite WAL。
2. **两级动态画像（信源 `source_id` + 主题标签 `tag`）**：
   - 采用贝叶斯平滑点击率 $\text{CTR}_{\text{smooth}} = \frac{\text{clicks} + 2\cdot\text{stars} + 1}{\text{impressions} + 15}$ 叠加时间衰减（半衰期约 30 天），实时转化成排序加减分，并让 `focus-selection.ts` 的展示席位随兴趣动态浮动（不再死锁静态 `14/7/4/3/6`）。
   - **已有历史立刻生效**：用现有 12 次点击与 5 条收藏初始化正向加权，曝光统计从上线后重新起算，不编造历史曝光。
3. **“多次曝光零点击 → 自动停分，除非很吸引人”状态机**：
   - **冷启动保护**：新源或近 14 天曝光 `< 8` 次不降权、不静默（防误杀低频精品源如 DeepSeek/Anthropic 官方）。
   - **降权（`cooling`）**：近 14 天有效曝光 `≥ 8` 次且 `0` 点击 `0` 收藏 → 排序降权（如 `-12` 分）、展示席位减半。
   - **自动不分配（`muted`）**：近 14–30 天有效曝光 `≥ 15` 次仍 `0` 点击 `0` 收藏（或手动点忽略）→ 不再分配常规席位，也不再为其消耗自动 AI 审译配额。
   - **破格直通阀（防错过震撼内容）**：静默源/主题若出现 **`ai_quality = 5`（重磅级）** 或 **规则高爆发（如高星飙升/跨 `≥ 3` 源报道/旗舰模型首发，`score ≥ 92`）**，仍可破格放行（每日最多 1–2 条，带「破格推荐」标记）；一旦你点击了其中任意一条，该源立即自动解冻恢复。面板里提供透明列表与「一键恢复/手动静默」。

### 四、Gemini Pro（Google AI Pro）订阅的“免费云电脑”能 24 小时部署吗？（联网核实结论）

**直接给结论：营销号说的“Gemini Pro 免费云电脑”不能直接拿来 24 小时稳挂 AI Radar；Google 生态里唯一能 24×7 常驻的是 GCP 永久免费 `e2-micro`（与 Gemini Pro 订阅无关），但搬上海外云会导致你最核心的「同济校园网免费 DeepSeek」直接断链。**

1. **常被误称“免费云电脑”的 3 个工具都不能 24h 挂机**：
   - **Google Cloud Shell**：闲置约 20 分钟自动休眠断开，有周时长配额且条款禁止跑常驻守护服务。
   - **Firebase Studio（原 Project IDX）**：同样闲置休眠，且 Google 已公告**停止新建并将于 2027-03-22 彻底关停**。
   - **Google Colab（Pro 送更高算力单元）**：Notebook 同样有闲置断连与运行上限，不是 24h 服务器。
2. **Google AI Pro 附带的每月 \$10 开发者抵用金**：确实存在（通过 Google Developer Program / AI Studio 领取），但社区实测**限制适用服务范围（偏 Vertex AI / GenAI 开发）**，直接开常规 GCP 虚拟机大概率不在抵扣范围内、会反扣绑定信用卡。
3. **GCP Always Free 永久免费 `e2-micro`（美国区）的硬限制**：
   - 1 GB 内存确实能 24h 跑 Node + SQLite（Linux 版），**但发往中国大陆的出站流量不免费（约 \$0.23/GB）**，必须套 Cloudflare Tunnel 等免费反代隔离出站流量，否则容易产生账单，且需外币信用卡验卡。
4. **对你当前 AI Radar 最致命的架构冲突**：
   - **同济免费通道会彻底失效**：你现在每天免费 100 次 / 每周 500 次的 `DeepSeek-V4.1-Flash` 依赖同济校园网内网 VIP（`10.67.0.251/252`），海外云主机根本连不进校内网，搬上云就只能换智谱免费层或 Gemini API 免费层/\$10 额度。
   - **不要做“云端 ↔ 本地同步 SQLite”**：双端同步 `radar.db` 极易锁库损坏；如果真上云，正确做法是**云端作唯一后端**，电脑和手机都直接浏览器/PWA 访问云端（复用已有的 PIN/Cookie 门禁）。

**3 条务实替代路线**：
- **路线 A（最省心、保住同济免费 DeepSeek）**：保持本地跑（开机自动设成静默后台计划任务，告别黑框常驻；反正重开时 15 分钟自动追平抓取），手机出门用 **Tailscale** 直连电脑。
