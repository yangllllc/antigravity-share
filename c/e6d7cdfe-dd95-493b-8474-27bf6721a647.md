### 一、浅色模式看不清的根因（已彻底修复）

- **根因（实测）**：Antigravity 的 `preload.js` 会在加载时通过**内联样式**将 `body` 背景切为宿主变量 `var(--background)`（浅色模式下变白），同时通过 `theme-change` 消息把宿主配色变量写入 `:root`。但旧版 `styles.css` 全部硬编码了深色模式专属浅色字（`#eef2ff`、`#cbd5e1`、`#93c5fd`、`#fde68a`、`#6ee7b7` 等），`app.js` 中还有一处内联浅绿色字体，导致切换浅色主题后变成“白底浅字 / 深黑弹窗浮在白底上”。
- **修复方式**：
  1. **对齐官方 `swarm_board` 宿主变量机制**：`styles.css` 全面改由宿主变量驱动（`--background` / `--card` / `--foreground` / `--muted-foreground` / `--border` / `--primary` / `--primary-foreground`），并为浅色模式（`:root`）与深色模式（`:root[data-theme="dark"]`）分别配置高对比度的语义状态色、弹窗、胶囊标签、下拉选项和滚动条。
  2. **实时双层主题同步**：`app.js` 优先监听 Antigravity 宿主发出的 `theme-change` 中的 `themeType`（实查主程序为 `light` / `hcLight` / `dark` / `hcDark`），并用 `MutationObserver` + 1×1 `canvas` 亮度采样兼容任意 CSS 色域（含 `oklch` / `color(srgb ...)`）及独立浏览器回退。
  3. **禁止旧样式缓存**：`main.mjs` 为 `/`、`/styles.css`、`/app.js` 和 `/api/*` 统一加上 `Cache-Control: no-store, no-cache, must-revalidate`，避免 WebView 残留旧 CSS。

## 一、为什么会这样？（实查结论）

1. **为什么左侧主栏和 `Settings` 里没有单独多出这个插件按钮**
   - 核查 Antigravity 主程序前端逻辑与运行时开关（`GetMendelFlags`）：左侧主栏插件独立分区（`x2c` / `pluginSidebarSection`）当前被特性开关 `enable-plugin-sidebar-section` 关闭；`Settings` 菜单项也是内置硬编码列表（`Account / General / Appearance / Notifications / Customizations / Browser / App / Shortcuts / Models / Developer / Running`）。
   - 第三方插件只能挂载到 Antigravity 开放的两个原生位置：**Customizations（插件中心）** 与 **对话右侧辅助面板（Extensions / Aux Pane）**。
2. **为什么观察一圈发现“多了两个项目”**
   - Antigravity 的语言服务会自动为带 Web UI 服务的插件创建一个**后台沙盒载体项目**。目前你的本地项目共有 4 个非临时项目 ID：
     - 你的真实业务项目：`Zemax`（已恢复到首位）和 `光路`；
     - 插件服务载体项目：`antigravity-archive-manager/archive_manager`（我们刚创建的归档管理后台服务）和 `swarm/swarm_board`（Antigravity 内置多智能体扩展自带的后台服务）。
   - 主界面左侧栏会隐藏这类带 `sidecar` 标记的服务载体，但 **`Settings` 设置页左侧的 `Projects` 列表（`YRb`）没有过滤掉它们**，所以你会同时看到它们。**不要手动删除这两个带 `/` 名称的项目**（插件面板里的“项目列表”已自动隔离它们，不会让你误删）。

#### 1. 核心功能（仿 ChatGPT + 本地安全增强）
- **已归档对话 / 全部对话**：
  - 统一中文列表展示标题、所属项目名称、对话步数、磁盘体积、最近活跃时间（北京时间）与归档状态；
  - 支持关键词搜索、按项目筛选、**多选批量操作**，单条或批量 **「恢复对话（取消归档）」「归档」「打开对话」「删除」**；
  - 优先调用 Antigravity RPC（`UpdateConversationAnnotations` / `DeleteCascadeTrajectory`）实时同步，若被权限策略拒绝则自动回退到本地 `.pbtxt` 与 `conversation_summaries.db` 原子同步。
- **项目管理与恢复（含 `Zemax` 专项诊断）**：
  - 自动检测 `projects/*.json` 与 `app_storage.json`，诊断 `Archived Only`、`Last 7 days`、`Group By`、`main-section-header` 折叠及 `projectsOrder` 缺失问题；
  - 支持 **「一键修复左侧栏异常设置」**、**「在此发起对话」**（为类似 `Zemax` 的空项目直接发起首条对话）、以及项目 **归档 / 取消归档 / 删除**（支持保护内置 Sidecar 专属项目，避免误删 `swarm/swarm_board` 等内置目录）。
- **插件回收站与孤立索引清理**：
  - 默认删除会先把 `.pbtxt`、对话 `.db/.db-wal/.db-shm`、`brain/<id>` 以及 SQLite 索引行快照完整备份到插件 `.trash/` 目录，支持随时 **一键还原**（需彻底清除时可在确认框勾选「彻底粉碎删除」）；
  - 自动识别并可清理无对应对话数据库的孤立 `.pbtxt` 索引残留（已检测到当前共有 `4` 条孤立 `.pbtxt`）。
