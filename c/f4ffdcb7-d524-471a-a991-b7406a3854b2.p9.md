### [T27/30 Part 1/2] Antigravity Assistant
**一句话结论**：ChatGPT 6.2 写的 **v5.2.0 工程底座非常扎实**（比 v5.1.0 明显更稳），完全值得以它为基线；但我在对现网代码审计和实测后，抓出了 **1 个会导致整理阶段必挂的致命 Bug 和 2 个实测短板**，现已全部修复并升级覆盖为 **v5.2.1**。

---

### 一、 v5.2.0 审计评价：哪些极强、哪些有暗坑

#### 1. 值得全盘保留的工程亮点
- **零凭据泄漏**：通过 `curl.exe --disable --config -` 从 stdin 管道注入 Bearer 与请求体，脚本和子进程命令行里不留密钥、也不落盘临时文件。
- **异步主调度 + Windows Job Object (`WorkerProcessGroup`)**：父进程跑异步事件循环，慢请求期间照样响应 `ping` 和 `notifications/cancelled`，超时或宿主退出时由内核 Job 对象连根清理 `curl` 进程树。
- **全包体句子级硬截断 (`Enforce-CompactBudget`)**：连同状态提示整段计数，确保 `delegate_to_deepseek` 恒定 $\le 1100$ 字符、`consult_tongji_brain` 恒定 $\le 900$ 字符，优先在句号/换行处收尾。
- **双内网 IP 建连回退 + 诚实降级**：`--resolve ...:10.67.0.251,10.67.0.252` 与显式降级提示。

#### 2. 实测揪出的 3 个真实缺陷（附实测证据）
1. **【致命 Bug】`DeepSeek-V4.1-Flash` 免思考字段丢失，导致 `math_check` 第二轮整理 100% 失败**
   - **根因**：v5.2.0 在 `Start-CampusCurlAsync` 第 315 行只传了 `chat_template_kwargs = @{ enable_thinking = $Thinking }`，删掉了 `thinking = $false`。而同济接口中 `Kimi` 认 `enable_thinking`，**`DeepSeek-V4.1-Flash` 只认 `thinking`**：实测（`task-413`）`only_enable_thinking` 仍会烧满 `reasoning_tokens=400`、`contentLen=0`，必须同时传 `thinking = $false` 才能关闭思考（`reasoning_tokens=0`）。
   - **实测后果**：在 `math_check` 实测（`task-386`、`task-408`）中，Wave 2 `DeepSeek 整理`（`MaxTokens=1500`）因默默开着思考耗尽 1500 `reasoning_tokens` 返回 `thinking limit`，两次全部退化为 **`整合未完成`**，并把第一轮 Kimi 盲算错的假数值（`631.6 nm` / `659 nm`）直接原样吐给了主模型！
2. **【逻辑损耗】`Read-CampusJobReply` 对触顶输出一律“一刀清零”**
   - 原版在 `finish_reason == 'length'` 时，即便 `message.content` 已经生成了 95% 的有效结论，也会被置为空串丢弃；且思考触顶时的 `reasoning` 尾段未保留给 Wave 2 做内部参考，导致重度题目容易直接报错或单路退化。
3. **【实测退化与 Prompt 短板】`c9eb2bf0` 长用例下 Kimi 首轮超时，且 PS 5.1 JSON 转义污染数学/代码符号**
   - 在 v5.2.0 上重放 `c9eb2bf0`（`task-383`）时，`Kimi 机制` 在 60s 处触发 `timeout` 仅剩单路结果；同时 `ConvertTo-Json` 会把 `<`、`>`、`&`、`'` 转义为 `\u003c` 等 6 字符编码，浪费 Token 且干扰数学/代码理解；且缺少针对“算术错误/伪反例驳回”与“勿让 Kimi 盲算复杂开方”的约束。

### 二、 v5.2.1 完善修改明细（已直接覆盖落盘）

已更新 `tongji_deepseek_mcp.ps1` 与同步副本 `tongji_deepseek_mcp.ps1`（UTF-8 BOM，SHA-256 一致：`8DEE6A62B7BDA2CA1C7E9F5AB4DDE1A316F8473FDC2B882825DDBCAE0AFFA178`），并同步版本号至 `deepseek-subagent.md` 与 `instructions.md`：

1. **修复双参数免思考控制**：仅在 `$Thinking = $true` 时保留模型默认思考；当 `$Thinking = $false` 时同时发送 `enable_thinking = $false` 与 `thinking = $false`，彻底恢复 `DeepSeek-V4.1-Flash` 的 10s 级免思考高速整理。
2. **分级挽救触顶输出（不向用户泄草稿，只供内部 Wave 2 复核）**：
   - `content limit` 时保留已有正文并标记达上限状态；
   - `thinking limit` 时仍**禁止**在 `Get-FallbackText` 中直接把原始 `reasoning` 吐给用户（严守 v5.2.0 原则），但提取最后 800 字存入内部 `Reasoning` 字段供 Wave 2 `DeepSeek 整理` 交叉复核，若 Wave 2 失败仍诚实降级或报错。
3. **Prompt 与长题抗超时优化**：
   - 新增 `ConvertTo-CleanJson` 还原 PS 5.1 对 `<`、`>`、`&`、`'` 的 `\u003c` 转义，保留 JSON 注入隔离同时减少 Token 噪音；
   - 明确禁止 Kimi 在 `math_check` 中盲算复杂开方，聚焦量纲与物理边界陷阱；在 Wave 2 显式要求**主动驳回探针中的算术误差与伪反例**、严禁复述原题；
