### 二、 当前同步触发与运行机制

1. **触发机制**：`hooks.json` 注册了 `Stop` Hook（`timeout: 25` 秒），每轮对话结束时执行：
   ```powershell
   powershell.exe -NoProfile -ExecutionPolicy Bypass -File sync_share.ps1
   ```
   （也可手动附加 `-SkipGitPush` 参数仅在本地生成静态文件）。
2. **日志解析（`sync_share.ps1` 第 174–233 行）**：
   - 遍历 `C:\Users\Administrator\.gemini\antigravity\brain\` 下所有合法会话目录，以共享读模式读取 `.system_generated\logs\transcript.jsonl`；当行内出现 `"truncated_fields"` 时，按行号下标回查 `transcript_full.jsonl` 补全截断内容。
   - 提取 `USER_INPUT`（经 `Clean-UserContent` 剥离系统标签并用 `Redact-Secrets` 脱敏）与 `PLANNER_RESPONSE`（`content` 经 `Redact-Secrets` 脱敏），按 `LastWriteTime.Ticks` 降序排序。
3. **页面渲染与 Git 推送（`sync_share.ps1` 第 260–312 行）**：
   - 将所有会话与模板 `template.html` 拼接，以 UTF-8 无 BOM 编码写入 `site\c\<id>.html` 及 `site\index.html`（最新一条会话）。
   - 未传入 `-SkipGitPush` 时，检查 `git -C site status --porcelain`，有变更则执行 `git add -A`、`git commit` 与 `git push origin main`（带低速超时参数，日志写入 `sync.log`），最后向 stdout 输出 `{"decision":"stop"}`。

### 三、 ~4000 字符截断问题的实测诊断

对现有 `site\c\*.html` 进行字符级统计后，暴露出**双重配额挤占**问题：

1. **固定页面壳开销**：所有 7 个 HTML 文件均内嵌固定 `5,827` 字符的 `<style>` 与 `1,811` 字符的 `<aside id="sidebar">`（且侧边栏随会话数量线性膨胀），尚未进入对话正文就已消耗大量体积。
2. **纯正文仍远超 4,000 字符**：7 个会话的纯文本正文 `MainPlainChars` 在 `2,276 ~ 19,026` 字符之间。以 14 轮典型长对话 `bb1e7994-b052-407c-8be9-f5c7c55e9456.html` 为例（总 HTML `30,580` 字符，纯文本 `12,975` 字符）：
   - `T1(user)=152`、`T2(ast)=1719`、`T3(user)=170`、`T4(ast)=2581`、`T5(user)=131`、`T6(ast)=1657` …… `T12(ast)=994`、`T13(user)=85`、`T14(ast)=2223`。
   - **关键推论**：即使完全剥离 `<aside>` 和所有 HTML 标签，若 `./c/<id>.md` 仍按“从第 1 轮到第 14 轮正序排列”，`12,975` 字符的纯文本依然会在第 4~6 轮处撞上约 4,000 字符提取上限，**第 14 轮最终断点仍会丢失**；同时，如果只做简单倒序而遇到某次 `T14` 自身超过 `3,500` 字符（例如大段代码/日志输出），单轮头部就会耗尽配额，导致 `T1` 初始目标和 `T14` 尾部结论双双被截断。
