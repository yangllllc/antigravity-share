本次核心矛盾在于：既要让强模型自由做跨会话语义归并、冲突覆写与边界判断，又要防止大输出触发约 60 秒网关断连、防止记忆膨胀撑爆常驻上下文、防止错误规则静默生效或反复回流。

  • 增量读取与水位线（extractor.py、redact.py）
  • 选型：隔离临时目录拷贝 SQLite（含 -wal/-shm）+ PRAGMA quick_check 重试后只读打开；按 conversation_id 独立维护 {last_step_index, anchor_step_hash, compact_sig, full_sig} 水位线；老对话续写自动附带前 1 轮 [CONTEXT_ONLY] 上下文，若文件截断或锚点行 SHA-256 漂移则自动全量重放。4 层防自污染（过滤 nesting_depth>0 子代理、哨兵标记与 /dream 识别、--exclude-cid、turn 级切片过滤）+ 13 类正则凭据脱敏 + 剥离 GENERIC 大输出 + 超长会话按轮次切分保证每批 ≤ 18,000 字符。

一、用大白话讲透：这套记忆系统到底是怎么运转的？

你可以把它理解成“大脑白天的聊天记录 → 晚上按需整理成笔记本 → 贴一张精简目录在桌面上”的三层结构：

[你每天的 Antigravity 对话] (底层明文 transcript.jsonl + summaries.db)
        │
        ▼ ① Python 脚本（隔离拷贝、跳过已归档/子代理、脱敏密钥、砍掉超长工具日志）
[干净的增量对话批次 batch_*.md]
        │
        ▼ ② Antigravity 强模型读批次 + 读旧索引 + 读你过去的驳回记录
[精简变更提案 proposal.json]（只说“新增/覆写/废弃哪几条”，绝不乱改原文件）
        │
        ▼ ③ Python 脚本验预算、查泄露、撞负反馈账本、算 Diff、渲染审阅页
[人工审阅闸门]（聊天直接批复 / 浏览器 review.html 一键确认）
        │
        ▼ ④ 自动建只读快照 → 原子写入 → 确定性重新编译桌面目录
┌──────────────────────────────────────────────────────────┐
│ Tier 0（绝不碰）：你手写的 core-reasoning-protocol.md / CONTEXT_*.md │
│ Tier 1 + Tier 2（自动编译到插件 rules/AGENTS.md，每次对话常驻，硬顶≤12KB）│
│   ├─ Tier 1：经你点头晋升的极少数“全局铁律”                          │
│   └─ Tier 2：一张极短的“主题目录表”（只写每个主题管啥、存在哪）          │
│ Tier 3（plugin_data/.../topics/*.md，平时不占上下文，聊到相关领域才读） │
└──────────────────────────────────────────────────────────┘

为什么这样设计？（核心好处）

  • 贴合 Antigravity 原生机制，零常驻负担：因为它是原生插件 antigravity-dream-memory，Antigravity 会自动在每次新对话加载它的 AGENTS.md（只是一张很轻的目录 + 极少数晋升规则，占不到 1.5 KB），而详细的踩坑经验全藏在 topics/*.md 里，聊光路才读光路、做 PPT 才读 PPT，不会越用越臃肿。
  • 能“改错”而不是“只增不减”：传统向量记忆库（RAG）只会越塞越多，新旧结论打架全靠碰运气；这套系统每次整理都对照旧条目，发现新结论推翻了旧结论时直接原地覆写并留一行“旧结论溯源”。
  • 重体力活全交脚本，防 60 秒断连、防误删、防死循环：
  • 脚本按每个会话记录“读到第几步 + 锚点哈希”，下次只抽新增发言；
  • 写盘前一定先锁死一份只读时间戳快照，随时能单条 revert 或整批 rollback；
  • 你只要驳回或撤回某条记忆，原因就会写进 feedback_ledger.jsonl，以后哪怕模型换个说法重新提议，也会被指纹+中文词袋重合检测直接拦下来。
