### 一、二次深度审查揪出并已提前修正的 5 处真实坑点

动手前逐行核对 `security.ts`、`feedQuery.ts`、`App.tsx` 与 `ai-settings.ts` 时，发现 5 个若按初版直接写会导致功能失灵的隐蔽问题，已在本次实现中全部封死：

1. **浏览器 10 秒公有缓存会吞掉刚点开的历史**：`security.ts` 原对未带 Cookie 的 `GET /api/items` 下发 `Cache-Control: public, max-age=10`。如果刚点开帖子立刻切去「最近浏览」，浏览器会返回 10 秒前的旧缓存导致新记录“消失”。已对 `preset=history` / `history=1` 豁免公有缓存，强制 `private, no-store`。
2. **默认 `sort=newest` 会覆盖历史倒序**：`feedQuery.ts` 原总是携带 `sort=newest`，会导致服务端 `applyChannelQuery` 里 `history` 的默认 `sort: "viewed"` 不生效（历史按发布时间而不是打开时间排）。已改为切换「最近浏览」自动切 `sort=viewed`，且关闭跨源 `merge` 与 3 天 `focus` 截断。
3. **非情报流页签下「最近浏览」入口会消失 & 键盘翻页触发 429**：`App.tsx` 在非 `feed` 页签硬编码只显示 `starred`/`hidden`，已补齐 `history`；同时 `security.ts` 原把所有 POST 归入 60 次/分钟写限流桶，快速按 `↓` 浏览会挤占收藏/已读配额，已把 `/view` 单独归入 240 次/分钟读桶并加前端 2s 去重。
4. **单配同济无智谱 Key 时单条翻译会被拦死**：`ai-settings.ts` 的 `translateSingleItem` 原先硬判 `!s.baseUrl || !s.model || !s.apiKey` 直接报错，未给同济放行；且 `config.ts` 静态读取 `TONGJI_API_KEY` 会妨碍运行时隔离测试。已改为动态读取 `getTongjiApiKey()`，并在 `aiReady()` 与 `translateSingleItem()` 同时识别同济与备用通道（同时严格尊重主开关 `s.enabled`）。
5. **同济双 VIP 切换绝不在发出请求体后重试**：`tongji-transport.ts` 在原生 `node:https` 上严格等 `TLSSocket` 的 `secureConnect` 完成后才执行 `req.write/end`，确保首 VIP 建连前失败切换备用 VIP（总建连 `≤5s`）绝不会造成一次请求重复计费。

### 二、`TONGJI_API_KEY` 存放位置有什么区别？怎么选？

当前 `config.ts` 已原生支持两类位置，读取优先级为：**系统环境变量 `TONGJI_API_KEY` > 同级 `.env.local` > 同级 `.env`**（Node 22 的 `process.loadEnvFile` 不会覆盖已存在的环境变量）：

| 存放方式 | 具体位置 | 优点 | 注意点 / 风险 | 适合场景 |
| :--- | :--- | :--- | :--- | :--- |
| **A. Windows 用户环境变量（推荐）** | 系统「环境变量 → 用户变量」新建 `TONGJI_API_KEY` | ① `release/AIRadar.exe` 与源码开发模式（`npm start`）**同时自动生效**；② 以后打包分享或云盘备份整个 `release/` 目录时，**绝不会顺手把你的学校密钥发出去**；③ 把 exe 挪到桌面或 D 盘照样自动认 | 设置后需重启一次 `AIRadar.exe`（从资源管理器新开窗口）生效；若换另一台电脑需重新配置（对个人校园 Key 反而是安全优势） | **仅在自己这台电脑用，追求零泄露与一劳永逸（首选）** |
| **B. exe 同级 `.env.local`** | `release/.env.local` 中写一行 `TONGJI_API_KEY=你的密钥` | ① 仅对这一个 `AIRadar.exe` 生效，不影响系统里其他程序；② 想临时软回滚直接把文件改名/删掉即可；③ `.gitignore` 已全局忽略 `.env.local` | 若以后直接压缩整个 `release/` 发给别人，须记得排除 `.env.local`；且源码根目录运行 `npm start` 时不会读 `release/.env.local` | **希望按目录隔离、随时记事本开关** |

> **如何立刻启用（任选其一，无需重打 exe）**：
> - 选 A：在 PowerShell 运行 `[Environment]::SetEnvironmentVariable("TONGJI_API_KEY", "你的密钥", "User")`，然后重新双击 `release\AIRadar.exe`；
> - 选 B：在 `C:\Users\<USER>\Desktop\ai-radar\release\` 下新建纯文本 `.env.local`，写 `TONGJI_API_KEY=你的密钥`，再重启 `AIRadar.exe`。
> - 启用后打开网页左侧 **「AI 引擎」→「同济校园网免费优先通道」** 卡片，点一下 **「重新探测」** 即可直观看到校内直连延迟、命中/回退计数与今日 `0 / 100` 消耗进度。

### 三、同济优先 + 智谱回退：最小改动方案

#### 1. 核心矛盾与 Node 22 直连选型
核心矛盾是：**在 SakuraCat（`tun0 172.19.0.1`）/ SDKDNS（`mihomo 198.18.*`）并存且可能开启系统代理的 Windows 环境下，既要强制同济流量绑定物理校园网卡直打内网 VIP `10.67.0.251/252` 防 403，又要保证现有 `glm-4-flash` 的公网普通路由与 Node SEA 单文件打包完全不受污染。**

- **拟采用方案：Node 22 原生 `node:https`（每请求 `agent: false` 独立短连接）**
  - **为何放弃 `undici.Agent`**：仓库已有前车之鉴（见 `http.ts#L200-L202` 与 `telegram.ts`），Node 22 内置 `undici` v7 与 `node_modules/undici` v8 混用会抛 `InvalidArgumentError: invalid onRequestStart method`，且在 SEA 单文件 `esbuild` CJS 打包中额外引入版本兼容风险。原生 `node:https` 零第三方依赖、完全忽略 `HTTP_PROXY`/`HTTPS_PROXY`/`ALL_PROXY` 和全局 `ProxyAgent`，且能精确分离建连/TLS 握手与响应体读取超时。
- **直连穿透关键实现细节**（新建 `src/server/enrich/tongji-transport.ts`）：
  1. **固定协议与关思考**：固定打 `https://agi.tongji.edu.cn/v1/chat/completions`，强制 `model: "DeepSeek-V4.1-Flash"`，请求体必带 `chat_template_kwargs: { enable_thinking: false, thinking: false }`。
  2. **物理校园 IPv4 出口绑定**：每次请求前实时枚举 `os.networkInterfaces()` 的非内部 IPv4：
     - 名称白名单匹配：`/WLAN|Wi-Fi|以太网|Ethernet|本地连接/i`；
     - 名称黑名单排除：`/Meta|wintun|TAP|VPN|vEthernet|Loopback|sing-tun|mihomo|Tailscale|WireGuard|ZeroTier|\btun\d*\b/i`；
     - IPv4 黑名单排除：`169.254.*`、`198.18.*`、`172.19.*`、`127.0.0.1`（保留 `100.64.0.0/10`，因本机实测校园 `WLAN` 即为 `100.78.136.128`，而 Tailscale 由网卡名黑名单拦截）。
  3. **应用层双 VIP 轮询与 ≤5s 建连硬顶**：
     - 绕坑说明：Node 22 在 `autoSelectFamily: false` 下，单个 `https.request` 的 `lookup` 即使返回多地址也只会连第一个。因此改为**应用层明确最多 2 次独立 `https.request` 建连尝试**（按轮询游标依次尝试 `10.67.0.251` / `10.67.0.252`，每次建连+TLS 握手定时 `≤2.5s`，总建连严格 `≤5s`）；
     - 自定义 `lookup` 同时兼容 `options?.all === true`（返回 `[{ address: vip, family: 4 }]`）与单地址回调，强制 `family: 4, autoSelectFamily: false`，保留 `servername: "agi.tongji.edu.cn"` 与 `rejectUnauthorized: true`；
     - **防双扣铁律**：仅在 `secureConnect` 完成前（尚未发送任何请求字节）建连失败时才切换备用 VIP；一旦 TLS 建连成功并写出请求体，严禁换 VIP 重试。
  4. **总超时与句柄回收**：独立 `AbortController` 控制总请求超时 **28s**（25–30s 可配），覆盖建连、响应头与完整 JSON 响应体读取；`finally` 必清理 `connectTimer`、`totalTimer` 并销毁异常响应流。

#### 2. 路由、回退、冷却与隔离设计（新建 `src/server/enrich/ai-router.ts`）
- **严格隔离**：`glm-4-flash` 继续走 `settings.key = 'ai'` 的独立 `baseUrl / apiKey / model` 与普通 `fetch`，绝不经过 `tongji-transport.ts`；`POST /api/ai/test`（草稿连通测试）显式传 `skipTongji: true` 保证只测表单里的智谱/备用草稿；另增 `POST /api/ai/tongji/probe` 供手动清冷却并单次实测同济。
- **即时透明回退**：同济返回 `401/402/403/429/5xx`、无物理网卡、建连/总超时、网络错、非法响应或空 `content`（含仅有 `reasoning_content` 而无 `content`）时，本次调用立即透明回退至 `glm-4-flash`；`reviewItems` 外层重试（`attempt === 1`）显式传 `skipTongji: true`，避免坏 JSON 重复打同济。
- **分级冷却与退避**：
  - 遇 `401/402/403`、无可用物理 IPv4 网卡、或双 VIP 均建连不可达（离校典型特征）→ 触发进程内长冷却（默认 **8 分钟**，5–10 分钟可配），期间零等待直走 `glm-4-flash`；支持手动重探清除，或到期后由单飞行锁放行 1 次自动重探。
  - 遇 `429` / `5xx` → 触发短退避（优先遵从 `Retry-After` 响应头并钳位在 15–120s，否则默认 60s），期间直接走 `glm-4-flash`，不连续撞限流墙。
- **非阻塞并发闸门（`≤2`）**：进程全局维护同济并发计数器（上限 2），使用非阻塞 `tryAcquire()`——若已有 2 路同济在跑且 `glm-4-flash` 就绪，第 3 路直接溢出走 `glm-4-flash`（零排队等待，仅无备用通道时短暂排队），`finally` 保证所有异常/中止路径释放槽位。
- **单通道就绪态处理**：`aiReady(s)` 仍尊重主开关 `s.enabled`；开启时只要「智谱就绪 **或** 同济有 Key 且未冷却未超预算」即返回 `true`。若仅配同济无智谱且恰遇离校，路由器返回明确类型 `unavailable`，不误标条目永久失败，待回校后自动恢复补译。

### 四、关于您的新想法：「点开概要即记浏览历史」与「存储增长/清理」

#### 1. 先算空间账（基于 `release/data/radar.db` 实测）
- 当前 1,650 条情报（含 973 条已读），**单条标题+摘要+正文+AI JSON 实测平均仅 `599 字节`**，全部正文数据总计仅 **0.94 MB**；主库 `radar.db` 3.23 MB（含索引），而 `radar.db-wal` 有 **4.19 MB**（WAL 日志尚未 checkpoint 回收）。
