### 一、`deepseek-stack` 真正值得我们学的 5 个思路（精炼提炼）

这个仓库名义上是给 DeepSeek 当拐杖，但剥离掉 7 个团队 GitHub PR 流水线技能和已被我们覆盖的部分（如 `ds-jury` 已被同济双核 MCP 覆盖、`ds-unslop` 已有更强的中文 `lieflat-less-ai-tone`、`ds-swarm` 已有原生 `swarm`）后，它有 **5 个元设计对强主力模型同样极具杀伤力**：

1. **双次失败即停的前提爆破（`ds-unstick`）**：同一个报错修了两次还复现，**禁止做第 3 次微调**。必须停手写出前两次共享的隐含前提（比如“我改的这个文件真的在运行吗”“环境变量真的生效了吗”），用最便宜的探针做 Yes/No 实测证伪，必要时 `git checkout/stash` 清现场换机制。强模型在环境坑、缓存坑里一样会钻牛角尖，这是全库最值钱的机制。
2. **外部真值 5 级举证阶梯（`ds-blast-radius` + `ds-mode`）**：把“我觉得没问题”拆成 L1 口述 → L2 指明 `file:line` → L3 路径推演 → L4 写小脚本运行反证 → L5 实机复现，并要求结论显式区分 `measured / inferred / guessed`。
3. **不缺额度时的终极增效器——盲评与局部嫁接（`ds-best-of-n`）**：对高价值任务（关键算法、复杂重构、重要 UI），用隐藏评分细则跑 3–5 个隔离工作区（Antigravity 原生支持 `swarm(workspace:"share", n:3)`），先运行淘汰不能跑的，选架构最好的作底座，**只把其余方案里的单个亮点函数或边界测试局部嫁接进来**，绝不整文件合并。你既然不缺额度，这是把算力直接兑换为质量上限的最稳方法。
4. **把确定性轮询封装为黑盒脚本 + 退出码（`ds-watch-pr`）**：全库唯一带脚本的技能，用 `watch_pr.py` 输出精简变化行与 `0/1/2` 退出码，不让 LLM 自己写循环、读大段原始 JSON 污染上下文。
5. **反规则膨胀的五级硬固化（`ds-lessons`）**：核心理念 *"An instruction an agent can skip is a wish"*——重复 ≥2 次的错误按 **架构结构 > 类型约束 > Lint/CI/Hook > 行为测试 > 文字规则** 固化，且**一旦硬约束生效，删掉对应的自然语言规则**。这恰恰和我们接下来要讨论的“规则/记忆膨胀”形成正面呼应。

### 三、核心架构推演：“不缺额度时，Skill 并入全局记忆/规则 vs 规则抽成 Skill，延续下去会怎样？”

这是你提得最有洞察力的问题。我们先推演两条极端路线延续半年后的真实终局，就能看清为什么**“不缺额度”也不能靠单纯的合并或拆分解题**。

#### 路线 A：不断把有用的 Skill 合并进全局规则或全局记忆（Always-on 膨胀）
- **短期体感**：爽。因为原本漏触发的流程变成每轮常驻，命中率立刻拉满。
- **延续下去的 3 个失效机制**：
  1. **未触上限先中“注意力稀释”**：大模型的有效指令遵循能力远小于它的最大上下文窗口。当你把 10 个不同领域的 SOP（写代码、做 PPT、跑统计、画图、发 PR）全塞进 `always_on`，中段规则会进入**静默失效**——模型不会报错，只是顺手把中间几条忘掉（你在外部双核交叉复审里也确认了这一核心约束）。
  2. **跨场景指令互相打架**：写科研论文讨论时被软件工程的“最小 diff / 少写 prose”拽偏，或者简单问答时被迫走繁琐的规划验证仪式，迫使你不停往规则里打“例外补丁”，文本越滚越厚。
  3. **触发 Antigravity 硬降级反而退回原点**：Antigravity 对 `always_on` 规则设有**单文件 24 KB 截断**和**总计 20,000 token 硬预算**；一旦超标，系统会自动把最大的规则文件从全文注入**静默降级为路径指针**（`- <path>: <description>`），兜了一大圈又退化回了“赌模型自觉去读”。
  4. **污染记忆的定位**：全局记忆（Dream）存的是**陈述性事实**（你的物理实验背景、本机 Python/FFmpeg 路径、踩过的平台坑）；把**程序性 SOP（怎么做某类任务）**塞进记忆，会导致每次 `/dream` 巩固和跨项目检索时事实与流程混在一起，极难维护。

#### 路线 B：把全局规则 / 记忆中的固定片段大量拆成 Skill（过度碎片化）
- **短期体感**：全局规则看起来极度优雅精简。
- **延续下去的失效机制**：
  1. **高频底层护栏跌落到概率触发区**：一旦把跨任务都需要生效的护栏（例如“先审前提”“双核前置检查点”“同错两次停手”）拆进自动发现 Skill，按照本机 `[MEM-AGY-002]` 的实测规律，绝大多数回合强模型会直接跳过它，变成“配置里写得头头是道，运行时几乎裸奔”。
  2. **你被迫记住几十个 `/skill-name` 口令**：系统变成了手动驾驶，反而增加了你每次发消息前的认知负担。

#### 真正能长期良性演化的结构：四层正交边界（不是二选一）

把“内容性质”和“触发要求”拆开看，答案就非常清楚了：

1. **Layer 1：Always-on 全局规则（只留跨任务不变量 + 硬触发路由表）**
   - 你目前 3 份全局规则合计才 **7,315 B（~7.1 KB）**，其实**非常精瘦健康**！
   - **适合放这里**：所有任务都成立的高层护栏（`core-reasoning-protocol.md`）、带客观信号的强路由（`deepseek-subagent.md`）、以及极紧凑的索引（Dream `AGENTS.md`）。
   - **不适合放这里**：超过 5 行的特定领域 SOP、仅在少数任务出现的长步骤清单。
2. **Layer 2：分层记忆（只存“事实与约束”，不存“操作流水线”）**
   - **适合放这里**：关于你本人、本机环境、课题上下文（`CONTEXT_<课题>.md`）、已证实的平台/工具坑点。
   - **从全局记忆抽成 Skill 的唯一合理情形**：如果你发现某条记忆里长出了一套**反复执行的多步脚本/操作手册**（比如“从实验数据到出图再到排版的一套固定命令”），那才应该把它从记忆里抽出去做成 Skill，而在记忆里只留一句指针和硬坑点。
3. **Layer 3：按需 Skill —— 必须分成“自动瘦身池”和“手动 `/命令` 池”两档**
   - **自动发现池（保持少而精，理想控制在高频 10–15 个以内，每条 description ≤200 字符只写“何时触发”，绝不写更新日志）**：留给高频、触发词极明确的场景（如做 PPT、画科研图、去 AI 味、统计分析）。
   - **手动召唤池（显式加 `disable-model-invocation: true` 或放到冷备目录）**：重型、低频或高侵入工作流（类似你本机已有的 `grill-me`，或者 `ds-best-of-n` 这种多路并行重活），**不占自动 `<skills>` 清单注意力**，想用的时候敲 `/skill-name` 100% 精准拉起。
4. **Layer 4：Lifecycle Hooks（`hooks.json`）—— 接管“最怕模型偷懒漏做”的硬红线**
   - 这是 `ds-lessons` 思路在 Antigravity 里的终极落地。凡是靠文字规则说了三遍模型还会忘的事（比如改动特定目录代码后没跑测试就想结束回合），用 `Stop` 或 `PreToolUse` Hook 做确定性检查，比把文字规则写长 10 倍有效得多。

*(注：我曾考虑过另一种方案——做一个类似 `ds-help` 的“总路由 Skill”，把其他 50 个 Skill 全藏在它的 `references/` 下，只留 1 个总入口给模型。后来放弃了这个方案，因为这会强行增加一轮“先读总目录 → 再读子 Skill”的二次跳转延迟，在高频单步任务里反而更容易被强模型嫌麻烦直接跳过；不如直接瘦身顶层清单 + 区分自动/手动两档。)*
