### 一、 实测排查真相：为什么双击桌面快捷方式还是旧画面？

1. 核查桌面唯一入口 `Antigravity 对话分享中心.url`，目标就是 `https://yangllllc.github.io/antigravity-share/`。
2. 用 `curl.exe` 绕过本地浏览器缓存直连线上实测：
   - 线上页面（`Last-Modified: 2026-11-18 10:38:54`）已经包含新的 **`⬇️ 下载 Markdown (.md)`**（`downloadMdBtn`）和最新对话 `8e491cda`。
   - 问题出在响应头 **`Cache-Control: max-age=600`**：您在改版前打开过一次网页后，浏览器把旧版 `index.html` 和 `sidebar.js` 强缓存了 **10 分钟**；随后您再次双击桌面快捷方式时，浏览器直接从本地磁盘缓存读取旧页，**根本没有向 GitHub 发请求**。

### 二、 本步追加的防缓存自愈改造（已提交推送 `c188c90`）

为彻底避免以后每更新一次还要干等 10 分钟，我刚刚在 `template.html` 与 `sync_share.ps1` 中追加了浏览器防缓存机制并重新推送：

1. **动态破缓存加载 `sidebar.js`**：在 `template.html` 底部改用 `sidebar.js?_t=Date.now()` 动态挂载侧边栏数据（`file:///` 离线打开时保持无参兼容），确保每次打开页面都能实时拉到最新会话列表与轮次。
2. **侧边栏链接自动带版本号 `?v=`**：`sidebar.js` 生成左侧导航链接时自动附加 `?v=<轮次>_<更新时间>`，任意会话有新增对话，跳转 URL 立即变化从而强制穿透浏览器和 CDN 缓存（顶栏“复制对话直链”依然只复制干净的无参 `.html` URL）。
3. **旧页缓存自动自愈刷新**：页面加载 `sidebar.js` 后会自动比对当前页 `data-conv-id` / `data-turn-count` / `data-update-time` 与最新快照；若命中浏览器旧缓存，经 `sessionStorage` 单次防死循环保护后自动 `location.replace` 跳至带 `?v=` 的最新版本。

**已验证状态**：`PARSE_ERRORS=0`，本地 `index.html`（`LOCAL_IDX_IS_INDEX=True | LOCAL_IDX_CACHE_BUST=True`）与 `sidebar.js`（`4643` 字节，`SIDEBAR_JS_HAS_GUARD=True`）均已生成并通过校验，新提交 **`c188c90`** 已推送至 `origin/main`（`PUSH_EXIT=0`）。

因为您浏览器里现在存着的那份“改版前”的旧 `index.html` 本身还没有这段自愈脚本且仍在 10 分钟缓存有效期内：
1. 请等待约 **30–60 秒**让 GitHub Pages 完成 `c188c90` 发布；
2. 然后在浏览器打开 `https://yangllllc.github.io/antigravity-share/`，按一次 **`Ctrl + F5`（强制刷新）**（或直接在地址栏打开 `https://yangllllc.github.io/antigravity-share/?v=1`）。

完成这一次强制刷新、让浏览器换上带自愈脚本的新版页面后，以后再双击桌面快捷方式就会一直自动拉取最新对话与按钮了。
