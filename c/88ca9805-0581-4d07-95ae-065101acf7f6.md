## 一、Supermemory 深度拆解与对比

> 以下关于 Supermemory 的事实均直接拉取并核验自 `supermemoryai/supermemory` 主仓库（31.7k Stars）、`apps/docs/*.mdx` 官方文档与 `supermemoryai/claude-supermemory` 插件源码 [实测]；本地记忆库现状核验自 `SKILL.md`、`store.py`、`fts_index.py` 及 `dream.ps1 status` 输出 [实测]。

### 1. 先戳破一个视频里常漏讲的前提：它并非“全开源”
- GitHub 仓库虽然挂 MIT 协议，但公开的仅是 **Web 前端、SDK、MCP Server、可视化组件 `@supermemory/memory-graph` 和各 IDE 插件外壳**。
- 它最核心的 **Learning Model + Temporal Vector-Graph Engine**（含自托管单二进制 `supermemory-server`）**代码均不公开**（其官方文档 `apps/docs/self-hosting/local-vs-enterprise.mdx` 原话写明：*"Its server source is not in the public repository."*）。本地免费版限 10,000 文档，需常驻后台进程、本地跑 Embedding 模型（默认 `Xenova/bge-base-en-v1.5`）并自备外部 LLM API Key 或本地 Ollama。

### 2. Supermemory 的核心原理与独特之处
它核心解决的是**“传统纯向量 RAG 不能当记忆用”**的问题（纯向量检索只会按相似度把“我喜欢 Adidas”和“我改买 Puma 了”一起召回，导致模型精分），拆成五块机制：

1. **Documents 与 Memories 双层分离**：原始文件/聊天存成 `Document Chunks`（做 RAG 查原文），后台 Learning Model（它也叫 `dreaming`）从中提炼原子事实存成活体 `Memories`。
2. **事实图谱三类关系边**：
   - `updates`：新事实取代旧事实（用 `isLatest` 控制检索只拿最新，同时保留版本链供审计）；
   - `extends`：给旧事实补细节但不推翻；
   - `derives`：跨多条事实自动推断隐含结论，打上 `isInference: true` 送进独立人工审阅队列（Approve / Decline / Undo）。
3. **时效与自动遗忘（`forgetAfter` / `isForgotten`）**：临时性事件（如“明天考试”“本周修认证 Bug”）到期后自动从检索路径淡出，防上下文腐烂。
4. **User Profile（`static` + `dynamic` + `buckets`）**：解决“非字面匹配”盲区（比如“我喜欢简洁回答”和“帮我规划行程”向量相似度几乎为 0，单靠 search 搜不到）。`static` 存长期稳定特征，`dynamic` 存带 `[YYYY-MM-DD]` 日期的近期动态，`buckets` 按主题分桶（满桶后自动聚合为 `aggregated_` 摘要），对话开始一次注入。
5. **Coding Agent 钩子与 SMFS**：
   - 看了 `claude-supermemory` 的真实源码：`SessionStart` 注 Profile；`UserPromptSubmit` **每轮由钩子脚本拿用户输入主动去搜记忆再注入**（不赌模型自己调工具，并用 `seenHashes` 会话内去重）；`Stop` 异步抓增量对话发给服务端。
   - **SMFS（Supermemory Filesystem）**：把记忆挂成目录让模型用语义 `grep` 和 `cat profile.md`（仅支持 macOS NFS / Linux FUSE 或虚拟 Bash，不支持 Windows 原生挂载）。

### 3. 和我们现有 Dream Memory 的横向对比

你当前生产库 [实测] 状态：**2 条 Tier 1 规则 / 6 个主题 / 21 条活跃记忆 / 30 个会话水位**，`AGENTS.md` 仅 20 行（约 2.4 KB，远低于 140 行 / 12 KB 上限），零外部依赖，33/33 测试全绿。

### 4. 哪些该放弃、哪些值得借鉴、到底要不要改？

#### 明确放弃的方向（及放弃原因）
- **放弃直接接入/替换为 Supermemory**：违背 `CONTEXT_dream_skill.md` 与 `mem2.md` 的多条铁律（闭源黑盒、绕过人工必审写盘、引入外部 LLM Key 或常驻本地 Embedding 吃你本来就偏紧的本机内存、增加 MCP 常驻 Token 税）。
- **放弃引入向量数据库 / Embedding 语义检索**：6 个主题 21 条记忆（即便半年后涨到 15 主题 80 条）根本没到向量检索的收益拐点，强上会打破“零第三方 pip 依赖”的干净架构。
- **放弃 `UserPromptSubmit` / `Stop` 每轮 Hook**：Antigravity 的 Hook 为同步阻塞，且你们在“排雷墓碑”里已明确否决每轮同步抓写。
- **放弃把 `dynamic` 近期动态常驻塞进 `AGENTS.md`**：你之前在 `rule_refine_20261120` 里特意收窄了 `AGENTS.md` 触发面，就是为了防无关背景污染当前任务；项目动态留在各自 `CONTEXT_*.md` 更干净。

#### 真正值得借鉴的 1.5 项（低侵入、高性价比）
1. **【唯一值得考虑的小代码改动】给条目增加可选的 `review_after=YYYY-MM-DD`（到期复核提醒，绝不静默自动遗忘）**
   - **为什么真有用**：看你现网的真实条目就能发现痛点——比如 `antigravity-platform.md` 的 `MEM-AGY-003` 记录了 `2026-11-17~11-23` Vertex 通道 Opus 误杀样本，还有 `agy-capsule v1.5.0+` 临时坑点、`optics-research-profile.md` 里的阶段性“在学”状态。过 1–3 个月这些条件变了，它们仍会挂着 `confidence=high` 僵死在库里。
   - **借鉴改造法**：在 `MemoryEntry` 头部注释里加一个**完全可选、向后兼容**的 `review_after=YYYY-MM-DD` 属性。到期后**不自动删除**，而是在 `check-due` 和 `extract` 产物里自动列出“已到期需复核的旧记忆清单”，让你在下一次 `/dream` 审阅时一键决定**续期 / 更新 / 退役**。
2. **【零代码规范借鉴】借鉴 `isInference`：区分“直接实测事实”与“跨会话推断”**
   - 无需改代码数据结构，只需在 `SKILL.md` 提炼规则里加一句：凡属模型跨会话归纳出的推断性结论，默认标 `confidence: "low"` 并在 `change_note` 写明 `[推断待确认]`，防止把猜测当实测沉淀。

#### 为什么我没立刻动手改？
- **时机与成本判断**：你的记忆引擎刚做完 4 轮审计封版，目前更紧迫的其实不是加新功能——实测 `dream.ps1 check-due` 已返回 `due: true`（`changed_conversations: 10`，达到 `>=5` 阈值），你可以先正常跑一次 `/dream` 感受真实运维摩擦，再决定要不要加 `review_after`。
- **高危共享层纪律**：`antigravity-dream-memory` 的 `scripts/` 与 `rules/AGENTS.md` 属于共享插件层（且我实测发现生产目录已多了 `fts_index.py`，而 `Desktop\memory\sandbox\scripts\` 尚未同步）。按规则，真要改前须先：**① 你确认要改哪一项 → ② 先只读跑 `blast-radius` 评估影响面并对齐沙盒/生产哈希 → ③ 沙盒 TDD 验证通过后部署 → ④ 审查**。

### 2. 怎么读最省额度、吸收率最高？（四步漏斗法）

**绝对不要**把 10 小时视频或整套未清洗字幕一次性丢进 AI 对话——不仅猛烧额度，超长上下文还会引发注意力稀释，最后给你吐出一堆空泛大纲。建议按下面 4 步走：

1. **第 1 步（0 视频成本）：先读“论文清单”，不先看视频**
   - CS329A 80% 的核心思想浓缩在官网每讲附带的 2–4 篇精选论文里。想看哪一讲（比如 Lec 3 或 Lec 14），直接把那 2–3 篇论文标题给我或去查摘要，花 10 分钟先搞懂**核心矛盾 + 核心机制 + 失效边界**，密度比听 80 分钟英语课高得多。
2. **第 2 步（零主额度初筛）：用免费工具吞长视频，主模型只吃“精华片段”**
   - 如果想听教授口头讲的直觉和 Q&A，先把想看的 3–4 节 YouTube 链接丢进 **NotebookLM**（免费、专啃长视频/多源资料），让它按你的问题提炼出时间戳和反常识观点；只有真正让你觉得“这 10 分钟点透了关键机制”的片段，再自己倍速看原片。
3. **第 3 步（如果要让本地 AI 精读单节）：本地洗掉时间戳，一节一节读**
   - 若某 1 节想让我结合你现有规则/代码做深度对照，只抓**单节**字幕（如 `yt-dlp --write-auto-sub --skip-download`），本地用几行 Python 去掉时间戳和重复行。一节 80 分钟英文课洗净后通常仅约 **1.0–1.3 万英文词（约 1.5 万 tokens）[推断]**，远在甜点区间内，一次精读 1 节完全不伤额度。
4. **第 4 步（防“学完就忘”）：每读完 1 节强制挂钩 1 个你自己的系统问题**
   - 例如读 Lec 3 时只回答一件事：“我现在的 `cross-model-reviewer` 和物理/代码任务里，哪些其实缺确定性验证器？”；读 Lec 14 时只回答：“`MemGPT` / `Cartridges` 里有没有哪一招值得写进 Dream Memory 的长期演进清单？”——拿不回一条可执行改动的内容，直接放过。
