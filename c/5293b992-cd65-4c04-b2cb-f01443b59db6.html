核心矛盾：Antigravity 原生 Automation（"builtin": "schedule"）只支持 App 运行期 cron 定时（无 OS 登录事件触发、未承诺离线漏跑补发），且直接挂 agentapi new-conversation 到点必开新对话消耗模型额度；同时本机全局权限为 TURBO + EAGER，无人值守会话必须靠多层硬闸门锁死人工审阅边界并防待审包堆积。

1. 实测与文档确认的硬边界

  • 真实加载路径 [实测 + 官方 sidecars.md]：全局 Automation 位于 C:\Users\Administrator\.gemini\config\sidecars\<id>\sidecar.json（或插件内 plugins/<plugin>/sidecars/<id>/sidecar.json）；内置 automation/SKILL.md 速览第 27 行的 ~/.gemini/jetski/sidecars/ 在本机不存在。
  • 启用与 agentapi 能力 [实测 + 文档]：
  • 须由用户在 Automations 面板（sidecar://dashboard）手动开启，不可由 Agent 改写 config.json；开启后系统自动绑定专属 projectId。
  • 本机 C:\Users\Administrator\.gemini\antigravity\bin\agentapi.bat 实测支持 agentapi new-conversation [--model=<flash_lite|flash|pro|model_id>] [--title=<title>] [--profile=<profile>] <prompt>。
  • 时区确认：本机为 China Standard Time（UTC+8），cron 须带 CRON_TZ=Asia/Shanghai 前缀且 restart_policy: "always"。
  • 离线补跑 [未验证]：官方 sidecars.md 未承诺关机/未开 App 错过 cron 点后的 catch-up，个人电脑设单一固定时刻（如每日 09:00）大概率频繁漏跑。
  • 自污染闭环 代码实测 [redact.py L138-145]：只要 agentapi new-conversation 的 --title 或首条 prompt 包含 [DREAM_INTERNAL_RUN]，即便未显式传 --exclude-cid，Layer B is_self_polluting_session 也会整会话跳过，不会形成自动触发自污染死循环。

  • 本机 TURBO 权限穿透风险：实测 config.json 当前为 permissionPreset: AGENT_PERMISSION_PRESET_TURBO、autoExecutionPolicy: EAGER、nonWorkspaceFileAccessPolicy: ALLOW。Automation 继承全局权限，仅靠 agent_permissions.access_grants 无法阻断无人值守会话误调 apply。守住人工审阅闸门须靠三层防线：① Prompt 硬禁生成 decisions.json 与调用 apply/revert/rollback；② governance.py 现有强绑定 plan_hash + decisions.json 契约；③ 建议加固：给 dream_cli.py 增加环境变量硬锁（如 DREAM_STAGE_ONLY=1 时从代码层直接拒绝 apply/revert/rollback，在 sidecar env 中写死）。
