### 一、两个项目的底层原理拆解

#### 1. `obra/superpowers`：用“强制注入 + 反借口 + 门禁流水线”治好 AI 偷懒
大模型写代码最大的通病不是“不会”，而是**跳步、凭感觉改、没测就宣称修好了**。Superpowers 用 4 个机制卡死这些坏习惯：
1. **SessionStart Hook 强制引导（`using-superpowers`）**：很多 Agent 装着 Skill 却忘了读；Superpowers 靠宿主启动 Hook 在会话第一帧注入元技能，强制规定“动手前先匹配 Skill，命中就没有跳过选项”。
2. **反合理化防线（Anti-Rationalization & Red Flag Table）**：针对模型爱找借口绕流程的倾向，在技能文档里写死“典型借口 → 驳斥现实”红旗表（如“这只是小改动不用写测试”直接判定违规）与铁律门禁。
3. **5 阶段硬门禁流水线**：
   - `brainstorming`（带 `<HARD-GATE>`，用户未签字拍板设计前严禁写代码）
   - → `using-git-worktrees`（切隔离工作树）+ `writing-plans`（拆成 2–5 分钟粒度的可执行步骤）
   - → `subagent-driven-development`（**每一步拉起干净无历史包袱的新子代理执行**，防长上下文腐烂，并强制 TDD `RED-GREEN-REFACTOR`）
   - → **双阶段审查**（先独立审 **Spec Compliance 需求合规**，再审 **Code Quality 代码质量**）
   - → `verification-before-completion`（无实跑命令输出禁止宣称完工）与 `systematic-debugging`（3 次失败强制停手质疑架构）。
4. **会话自诊（`diagnosing-superpowers`）**：Agent 跑偏时，直接让它按会话日志做行级取证，定位哪一步跳过了门禁。

#### 2. `TencentCloud/Octop`：把个人/小团队 Agent 收敛进一个“本地单进程中枢”
Octop 走的是“本地优先、零微服务运维负担”的运行时路线，核心拆成三件独立可演进的 Python 库：
1. **`octop-harness`（运行时引擎）**：基于 LangChain `deepagents` 与 LangGraph Checkpoint，按 L0（I/O）→ L1（工作区后端：本地/Docker/S3/PG）→ L2（业务逻辑）→ L3（装配）严格分层；支持多模型路由（`ChatModelFactory`），并提供 **ACP（Agent Client Protocol）** 协议，可反向桥接终端/IDE 编程代理。
2. **`octop-gateway`（多通道 IM 网关）**：用统一的 `BaseChannel` 异步事件流 + 原生流式输出，抹平微信、企微、飞书、钉钉、QQ、Telegram、Discord 等 10+ 聊天软件的差异。
3. **`octop-memory`（零依赖分层记忆）**：仅用 Python 标准库 + **SQLite / FTS5**（可选 PG），做 **L0 → L3 阶梯蒸馏**（原始对话事件 → 原子事实 `AtomCard` / 实体页 / 情节），带词法检索、去重、Token 预算控制，以及可跨宿主导入导出的 `.hmpkg` 迁移包。
4. **单进程整合**：一条 `octop run` 同时拉起 Web 控制台、CLI、Cron 定时任务、多用户 JWT 隔离、无头浏览器与远程桌面操控，全部数据落本地 `~/.octop/`。

### 三、最值得落地的 4 项低摩擦升级 vs 3 项应果断放弃的设计

*(注：本轮已联动同济双核做了架构边界复核；其中 Kimi 骨架超时，DeepSeek-V4.1-Flash 精确标出了三处隐蔽依赖——宿主 Hook 生命周期、`git worktree` 在非 Git 目录失效，以及 Windows Job Object 会回收常驻 Python/SQLite 进程。以下方案已全部避开这些坑。)*

#### ✅ 值得落地的 4 项增量升级（零常驻 Token 膨胀）
1. **给异构审稿补上“Spec → Quality 两段检查顺序”**（借鉴 Superpowers 双阶段审查）
   - **落点**：微调 `cross-model-reviewer.md` 的成稿校读 `brief`（只加 1 句话，不增轮次、不增额度）。
   - **收益**：目前审稿是一次性抓硬伤，审稿模型容易沉迷挑局部公式/代码细节，却忽略整稿漏掉了用户的某条核心约束。改成“先核 Spec 合规（有没有答偏/漏条件），再核 Quality（推导/代码/边界反例）”，白嫖一层需求防漂移。
2. **做一个“会话日志与 MCP 触发率自诊”轻工具**（借鉴 `diagnosing-superpowers`）
   - **落点**：新增轻量按需脚本/Skill（或挂进 Dream 插件），直接解析本机 `transcript.jsonl` 与 `tongji_mcp_metrics.jsonl`。
   - **收益**：以后觉得某次对话“变笨了 / 忘调 Skill / MCP 偷懒了”，一键出证据链报告（哪一轮该触发未触发、思考字数异常点、重试/超时分布），替代手工翻日志，直接配合 `mcp.md` 的一周复盘。
3. **补齐“长任务分步干净子代理执行”模式**（借鉴 `subagent-driven-development`）
   - **落点**：不新增常驻规则，在需要改 4+ 个独立模块/批量科研脚本时，主会话只管拆解与验收，每步通过原生 `invoke_subagent`（干净上下文）完成并跑实测验证，主会话只收回简短 diff 与验证证据。
   - **收益**：防长对话中后期上下文污染降智，同时直接压低主会话后续轮次的 Token 重复输入。
4. **给 `antigravity-dream-memory` 补一层“按需只读 SQLite FTS5 索引 + 导入导出”**（借鉴 `octop-memory`）
   - **落点**：在 `antigravity-dream-memory/scripts/` 中增加一次性构建/查询命令（**严禁做成常驻后台服务**，避开 Windows Job Object `KILL_ON_JOB_CLOSE` 回收坑，也保持 `AGENTS.md` 常驻体积不涨）。
   - **收益**：现在只有 6 个 topic 手工按表翻够用；等未来积累到 20+ 课题/上百条记忆时，按关键词毫秒级跨主题召回，并支持把记忆打包迁移到其他环境（如 Codex）。

#### ❌ 考虑过但建议果断放弃照搬的 3 类设计
1. **放弃照搬 Superpowers 的“强制 TDD + Git Worktree + 2–5 分钟细粒度 Plan”刚性流水线**：你的高频场景包含光学科研推导、PPT/论文撰写和大量非 Git 个人目录脚本——强推 TDD 与 Worktree 在非 Git 目录直接失效，且严重违背你反感微操 SOP 的铁律（把冗长的反合理化红旗表塞进常驻规则还会反向拉低规则遵循率）。
2. **放弃把 Octop 全家桶装成主力底座来替代 Antigravity**：Antigravity 2.0 已内置多模型、Swarm、浏览器/生图子代理、Sidecar 与定时器；在本地再跑一套基于 LangGraph 的 `octop-harness` 会造成规则、记忆、工作区双套分裂。**唯一例外**：如果你明确需要“出门用手机微信/飞书远程遥控家里电脑”，才考虑把 Octop 当独立外部进程仅用作 **IM 网关 + ACP 桥接**。
3. **放弃把 Superpowers 全套 14+ 个 Skill 整包丢进自动发现池**：你之前在 `antigravity-platform.md` 已实证过，自动 Skill 池塞满重叠或臃肿描述会稀释注意力，反而把高频科研/排错技能的触发率拖垮。

### 四、为什么你觉得 Gemini 4 Neon 额度消耗得好慢？

直接结论：**不是 `xhigh` 单次变便宜了，更可能是“官方刚扩过缓存池 + 你的架构在替 Neon 挡刀 + 当前对话形态没踩中烧卡重灾区”三者叠加。** 按证据级别拆解如下：

1. **[公开信息] 官方 2026 年 11 月刚大幅扩容了 Neon 缓存池并重置过额度**
   - Neon 刚上线 Antigravity 时，社区（X / Reddit / V2EX）曾普遍反馈重度写代码极不耐用，核心原因是当时后端 Cache Pool 偏小、对话稍有停顿缓存就被逐出，导致每轮把整段历史重算一遍。
   - 随后 Antigravity 负责人 Varun Mohan 公开确认并上线了大规模 **Cache Pool 扩容**（缓存命中率提升约 4%，官方口径称同额度可多完成至少 **20%+** 的工作），同时向受影响用户统一执行了**额度重置（Quota Reset）**。如果你刚好在优化后或重置后体验，体感会明显比刚上线时耐用很多。
2. **[本机实测] 你的“外脑卸载 + 精简稳定前缀”确实在大幅省额度**
   - 查本机 `tongji_mcp_metrics.jsonl`：仅 `11-23` 至 `11-24` 就记录了 **20 次**调用，把大量深度推演、架构骨架和代码审计卸载给了校内免费的 `Kimi-K3.1-Pro` × `DeepSeek-V4.1-Flash`（对照 `mcp.md` 中 `c9eb2bf0` 光学对话 0 调用 MCP 时 Gemini 单次自烧 3.2 万字思考）。
   - Dream 记忆把常驻 `AGENTS.md` 硬压在 ≤140 行、按需读 `topics/*.md`，规则前缀短且稳定，非常容易持续命中 **Prompt Cache**（缓存命中的输入开销远低于未命中输入与长思考输出）。
   - 内置 `browser` 子代理默认走 `flash` 等轻量分流，没有全压在 Neon 上。
3. **[推断] 对话形态 + “更强所以返工更少”的间接红利**
