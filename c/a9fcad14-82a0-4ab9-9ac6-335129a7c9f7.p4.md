### [T2/4 Part 3/3] Antigravity Assistant
- **自动发现池（保持少而精，理想控制在高频 10–15 个以内，每条 description ≤200 字符只写“何时触发”，绝不写更新日志）**：留给高频、触发词极明确的场景（如做 PPT、画科研图、去 AI 味、统计分析）。
   - **手动召唤池（显式加 `disable-model-invocation: true` 或放到冷备目录）**：重型、低频或高侵入工作流（类似你本机已有的 `grill-me`，或者 `ds-best-of-n` 这种多路并行重活），**不占自动 `<skills>` 清单注意力**，想用的时候敲 `/skill-name` 100% 精准拉起。
4. **Layer 4：Lifecycle Hooks（`hooks.json`）—— 接管“最怕模型偷懒漏做”的硬红线**
   - 这是 `ds-lessons` 思路在 Antigravity 里的终极落地。凡是靠文字规则说了三遍模型还会忘的事（比如改动特定目录代码后没跑测试就想结束回合），用 `Stop` 或 `PreToolUse` Hook 做确定性检查，比把文字规则写长 10 倍有效得多。

*(注：我曾考虑过另一种方案——做一个类似 `ds-help` 的“总路由 Skill”，把其他 50 个 Skill 全藏在它的 `references/` 下，只留 1 个总入口给模型。后来放弃了这个方案，因为这会强行增加一轮“先读总目录 → 再读子 Skill”的二次跳转延迟，在高频单步任务里反而更容易被强模型嫌麻烦直接跳过；不如直接瘦身顶层清单 + 区分自动/手动两档。)*

### 四、要不要根据 `deepseek-stack` 自制一个 Skill？以及下一步怎么走？

在动手新建之前，我不替你过早拍板，提供 **3 条可以自由组合的推进路线**（附各自代价）：

1. **路线 1：先给现有技能库做一次“体检减脂”（最推荐作为第 0 步）**
   - **做法**：① 先跑一段只读统计脚本，查你过去历史对话的 `transcript.jsonl`，看这 53 个 Skill 里到底**哪些被真实 `read_file` 触发过、哪些至今 0 次**（外部可证伪验证，靠数据不靠猜）；② 清理 5 个与插件重复挂载的目录；③ 精简 `wps-office-suite` 等超长 frontmatter（把 2,000 字更新日志移出 `description`）；④ 把低频/重型 Skill 标为 `disable-model-invocation: true` 转为手动 `/命令`。
   - **收益 / 代价**：立刻提升你现有所有好 Skill 的真实自动命中率；代价仅需 10 分钟审核清理清单。
2. **路线 2：微升级全局护栏 + 自制 1–2 个高杠杆专属 Skill（吸收 `deepseek-stack` 精华）**
   - **微升级现有全局规则**（不膨胀，总计仅增 ~6 行）：在 `core-reasoning-protocol.md` 里补两条跨任务通用铁律——① 同一故障连续 2 次修复失败即强制停手验共享前提（`ds-unstick` 核心）；② 关键结论显式区分 `实测 / 推断 / 待验`。
   - **自制 1–2 个高价值手动/半自动 Skill**（采用 `deepseek-stack` 的 `Steps + Hard Stop When + Rules` 紧凑风格，单文件控制在 2 KB 左右）：
     - 候选 A：`debug-unstick`（或合并成 `verify-and-unstick`）——专治卡壳排错与高危改动，融合 `ds-unstick`（前提探针 + 清场换路）+ `ds-blast-radius`（5 级举证阶梯）+ 联动你的同济双核 `code_audit` / `test_forge`。
     - 候选 B：`best-of-n`（手动 `/best-of-n` 触发，`disable-model-invocation: true`）——专为“不缺额度追求极致质量”定制，直接调用 Antigravity 原生 `swarm(workspace:"share", n:3)` 跑盲评打分 + 局部嫁接。
   - **代价**：新增 1–2 个精准技能，几乎不增加自动清单负担。
3. **路线 3：直接实验 1 个确定性 Hook（把 `ds-lessons` 真正跑起来）**
   - **做法**：挑 1 个你日常最烦的“模型口头说好了但没实测/漏了某一步”场景，在 `~/.gemini/config/hooks.json` 或具体项目 `.agents/hooks.json` 里写一个轻量 `PreToolUse` 或 `Stop` 校验脚本。
   - **代价**：需要定义明确的触发条件（避免误拦日常纯聊天回合）。
