### 三、逐仓源码拆解与取舍推理

#### 1. `promptfoo/promptfoo`
- **考虑过的正向场景**：仓库内置 `.claude-plugin/marketplace.json` 与 4 个评测/红队 Skill，支持声明式 YAML 断言矩阵和 `exec:` 外部脚本 Provider，理论上可把 `ablation-bench` 的 `invoke_codex_review.ps1` 封装进去跑批量回归。
- **放弃原因（实测）**：
  1. **遥测红线一票否决**：直读 `src/telemetry.ts` 与 `src/constants.ts`，默认同时向 PostHog（`https://a.promptfoo.app`）与自建 `R_ENDPOINT`（`https://r.promptfoo.app/`）发送含 `user_id`、`email`、`nodeVersion`、`platform`、`arch` 的遥测；即便设置了 `PROMPTFOO_DISABLE_TELEMETRY=1`，`record()` 仍会走 `recordTelemetryDisabled()` → `sendEvent('feature_used', { feature: 'telemetry disabled' })`——它只关了 PostHog，**`fetchWithProxy(R_ENDPOINT, ...)` 仍会发出一次带身份与环境信息的 HTTP POST**。
  2. **无真实痛点且无法覆盖主场景**：本机 `ablation-bench` 主测 Antigravity 桌面订阅内原生空白子代理（无对外 API Key 池），规模仅 8 组定向 `n=1` 诊断，也不做公网 LLM 应用的 OWASP 漏洞扫描。为此引入 74 个生产依赖的 CLI 属于典型“为找工具而造需求”。
- **边界条件**：仅当未来你开发面向外部用户的独立 LLM API 服务并需要 CI 自动化回归/红队门禁时才值得重评，届时须在防火墙/代理层额外屏蔽 `r.promptfoo.app`。

#### 2. `google/adk-go`
- **考虑过的正向场景**：除 Go SDK 本身外，仓库 `.agents/skills/` 下藏有 `adk-go-self-review`（182 行）与 `adk-sample-creator` 两份官方维护者 Skill，检查是否能直接移植到本机。
- **放弃原因（实测）**：
  1. **主框架完全不在本机生态**：`go.mod` 硬要求 `go 1.26.10` 并强绑定 `cloud.google.com/go/aiplatform`、`otel`、`a2a-go`、`google.golang.org/genai`，本机无 Go 工具链且全部桌面项目均非 Go。
  2. **仓内 Skill 高度绑定 Go 语义**：`adk-go-self-review` 聚焦 `iter.Seq2` 流式 `yield`、goroutine 资源释放、concurrent map write 与 Google Go Style Guide，不可直接复用。
- **零成本可留思路（不建规则/Skill）**：`adk-go-self-review` 中有两条通用工程习惯值得口头记住——① **绝不在写代码的同一会话里做最终自审，必须在新上下文看完整 diff**（本机已由 `cross-model-reviewer` 不 `fork` 历史与 Codex `scheme-redteam-review` 实现）；② **变异自检（Mutation Check）**：写完关键分支（如 `if a && b`）与测试后，逐个临时删掉或反转单个条件再跑测试，确认测试真的变红，专防“只测了一半条件”或“常量自洽假测试”。

#### 3. `DietrichGebert/ponytail`
- **为什么重点深读源码**：200k★、MIT、实查全部 `hooks/*.js` 零外网/零遥测，且 `INSTALL.md` 明确列出了 Antigravity CLI 与 Codex 支持，是最容易让人心动的候选。
- **逐项拆解与放弃原因（实测）**：
  1. **基准结论不能直接外推到本机**：直读 `benchmarks/results/2026-10-07-agentic.md`，其 `-53%` 代码、`−45%` 输出 token、`−41%` 耗时来自 **Opus 5.5 在 FastAPI+React 业务仓库与小型 Web App 上跑的 39 题（585 场）且全程禁用 Bash（No shell, by design）**。关键细项容易被首页横幅掩盖：
     - 18 道带隐藏测试的正确性/安全题上，三组几乎持平（无 Skill `86/90 = 95.6%` vs Ponytail 5 `87/90 = 96.7%`）；
     - Sonnet 5.5 盲评“回复对忙碌开发者的可读实用度”，Ponytail 5 相对无 Skill **没有显著优势，反而略逊（`82 : 106, p = 0.09`）**；
     - 你的主力场景是物理/光学公式推导、COMSOL/MATLAB/Zemax、论文与 PPT、以及少量 Antigravity 工具/Sidecar，而非高频 CRUD 前端手搓组件；若把“少说多删”常驻进全局，还可能与 `core-reasoning-protocol.md` 第 0 节“复杂问题外显关键推理与放弃方案”产生行为拉扯。
  2. **本机平台与容量红线硬冲突**：
     - **Antigravity 端**：按 `INSTALL.md`，装插件会一次灌入 6 个 Skill（`ponytail` / `ponytail-review` / `ponytail-audit` / `ponytail-debt` / `ponytail-gain` / `ponytail-help`），立刻突破 ~20 自动 Skill 软上限（其中 `ponytail-gain` 只打印静态 ASCII 基准图，纯占注意力）；且官方注明 Antigravity 无生命周期 Hook、档位不持久化；若把 `AGENTS.md` 贴进常驻规则，则撞破 4 份 `always_on` 硬封顶。
     - **Codex 端**：实查 `hooks/claude-codex-hooks.json`，3 个 Hook 全裸调 `node -e ...`，`INSTALL.md` 明确提示 PATH 无 `node` 时每次 Hook 都会报 `node: command not found`——与本机 PATH 无 `node` 现状直接冲突，且破坏 Codex“4 核技专司只读红队”的收拢定位。
  3. **核心价值已被本机护栏覆盖**：其 `/ponytail-review` 强调的“改函数前 grep 全部调用方、追 diff 之外的破坏”已由本机 `blast-radius`（L1–L5 实测举证）+ `cross-model-reviewer` 覆盖；前端优先用浏览器原生能力不乱引包已由离线版 `modern-web-guidance` 覆盖。
- **零成本可留思路（不装包、不加规则/Skill）**：如果后续开发 `ai-radar`、Sidecar 或科研脚本时担心 AI 顺手封装过度，可在当次需求里直接口头用它的两条精髓——① 按“已有代码 → 标准库/原生 → 已有依赖 → 最小代码”选方案，但绝不削边界校验与安全；② 刻意留下的简化妥协随手写一行 `# shortcut: <边界上限>, <触发升级条件>` 注释，避免“以后再改”静默腐烂。
