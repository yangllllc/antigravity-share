痛点 1：打开要手点抓取，且等好几分钟才进新东西

实测根因（来自 collectors/index.ts 与库内 runs 记录）

  • 最大元凶：采集过程被 AI 同步阻塞。单机版虽然不用推送，但默认仍走了 pushTiming = "wait_ai"（collectors/index.ts）——每抓完 1 个源，都要原地死等智谱 glm-4-flash 同步审完并跑完语义去重，才肯去抓下一个源。库内实测铁证：
  • rss-qbitai 无新增时仅 0.2s，新增 1 条耗时直接飙到 22.1s；
  • github-ai-trending（+11 条）卡了 43.3s、github-mcp-tools（+10 条）卡 36.2s、cctv-news（+9 条）卡 31.3s。
  • 30 个启用源全串行 + 90 秒纯空等 + 失败源双倍超时：
  • runAll() 逐个串行跑 30 源，且每源之间硬等 sourceGapMs = 3000ms（collectors/index.ts），光空等就白费 90 秒；
  • 库内 settings 尚未保存代理配置，v2ex-share、hf-daily-papers、rss-bbc-zh、rss-deepmind-blog、rss-google-ai-blog、rss-hf-blog 6 个海外源连续失败，而 http.ts 在 curl 超时 7s 后又自动回退 fetch 再等 7s（实测 v2ex-share 每次精准卡死 14.0s）；github-deepseek-releases 因无 Token 触发 GitHub 匿名限流 HTTP 403。
  • 打开网页无自动快刷与进度反馈：
  • 启动时 startIntervalScheduler() 虽然会跑到期源，但很多源间隔是 2–6 小时（未到期不跑），一旦排在前面的慢源/失败源卡住，打开前几分钟完全看不到新内容；
  • 点「立即抓取」后前端只在 4 秒后盲刷一次列表（App.tsx），没有进度条也不会边抓边自动刷出新条目。

改造方案（目标：全量刷新压到 15–30 秒，打开即自动流式出新）

  • 采集与 AI 彻底解耦：采集管道只做「抓取 → 规则粗滤 → 立即落库可见」，AI 审核/翻译/去重全部改走后台异步队列，单源耗时回到 0.3–2 秒级。
  • 双轨受控并发 + 去掉双倍超时：国内源与海外源分池并发（如总并发 5–6，同域名串行 + 短间隔，GitHub 单独限速防 403），取消 3 秒全局源间死等；修复 http.ts 超时失败后不再二次重复超时。
  • 打开即静默增量刷新 + 实时进度条：启动时若距上次抓取超过阈值（如 15 分钟）自动触发一轮并发快刷；顶栏实时显示 正在抓取 14/30 · 新增 +9 条，每完成几批就自动热更新列表，不再干等。

痛点 2：新旧内容分不开 + 点开看中文翻译就误标已读

实测根因

  • 外文列表预翻译覆盖率极低：库内 1145 条有效条目里，仅 52 条有中文标题（titleZh）、28 条有中文正文（summaryZh），绝大多数外文只能靠点开详情触发单条翻译。
  • 点开看译文与标已读强绑定：App.tsx 的 openDetail() 在打开详情抽屉的瞬间无条件写入 read = true，结果只是想看懂一条英文讲什么，就被标成已读。
  • 精选排序让旧帖常驻顶部，缺乏「本次新收录」标记：默认「半小时精选」按 ai_quality DESC, score DESC 排（routes.ts），三天前高分老帖霸顶、刚收录的新条目混在中间，且列表只显示原帖发布时间，看不出哪批是刚抓进来的。

改造方案（把「新旧 / 中文翻译 / 已读状态」三件事拆干净）

  • 后台自动预翻译列表（免点开直接看中文）：
  • 只要配了智谱免费 Key，后台异步队列优先给首页精选池和最新未读外文批量补齐 titleZh（中文标题）+ takeaway（1–2 句中文大白话要点），写库缓存。
  • 列表直接展示中文标题与要点，扫一眼就知道值不值得点开，无需为了看懂而点进详情；点进详情再按需补全长文 summaryZh。
  • 「看翻译」与「标已读」解耦（提供 2 个交互口径供你选）：
  • 方案 2A（推荐）：列表直接出中文；点开详情抽屉不再秒标已读，改为「点击去原文链接 / 手动点底部『已读并下一条』 / 或停留超过 4 秒」才标已读，抽屉与列表行均支持一键切换已读/未读。
  • 方案 2B：列表同样后台自动出中文，保留「点开详情即已读」，但把已读条目明显沉底/淡化，并在顶部给一个显眼的「只看未读」主切钮。
  • 「新收录」水位线与视觉分层：
  • 记录你的上次访问水位线（last_visit_at）：比上次打开更新入库（first_seen_at > 水位线）的条目挂醒目 NEW 徽标，支持顶部一键切「本次新增 / 未读」，并提供「将当前已看内容归档（推进水位线）」按钮；
  • 半小时精选默认未读优先、已读自动沉底，不再让看过的老高分帖一直占在最前面。

| 路线 | 实现方式 | 体验与优势 | 代价 / 限制 |

| :--- | :--- | :--- | :--- |

| 路线 A：电脑后端 + 手机 PWA 桌面图标（最快、零成本、双端实时同步） | 给 AIRadar.exe 加「手机局域网/远程访问」开关（监听 0.0.0.0:8788 + 非本机访问强制 PIN 口令防校园网旁人误连 + 网页展示扫码二维码），前端补齐 PWA manifest 图标；安卓浏览器扫码打开 →「添加到主屏幕」，全屏无地址栏运行 | 最快今天就能用；手机和电脑共用同一份 radar.db（已读/收藏/翻译缓存实时同步）；手机零耗电、不用在手机折腾代理 | 依赖电脑开机运行 AIRadar.exe（可顺带做后台静默托盘/开机自启）；离开同一 Wi-Fi 在外访问需在电脑和手机装免费 Tailscale 组网（且 Tailscale 可自动给 HTTPS） |

| 路线 B：免费云端托管版（电脑关机手机也能随时看） | B1 纯免费静态版：GitHub Actions 每 1–2 小时自动抓取+调智谱翻译生成静态 PWA 部署到 GitHub Pages；<br>B2 云主机动态版：把现成 Node + SQLite 部署到一台常驻小 VPS / 免费云容器 | 电脑关机也能随时刷，海外源天然直连不用代理，手机同样可添加到主屏幕当 App 用 | B1 零费用，但手机/电脑的已读与收藏各自存本地不互通、不能随时手点实时抓取；B2 体验最完整且双端同步，但需要一台常驻服务器（或学生免费云主机） |

| 路线 C：真正独立的 .apk 安卓安装包 | C1 轻量套壳 APK（Capacitor）：把现有前端直接打成 .apk，后端仍连路线 A（电脑）或路线 B（云端）；<br>C2 纯手机离线独立 APK：在手机端重做抓取引擎 + 本地 SQLite + 直调智谱 | 真 .apk 可安装；C2 可完全脱离电脑和服务器独立运行 | C1 只是给 PWA 换了个 .apk 壳，体验几乎相同但要引入 Android SDK 构建链；C2 相当于重写一套安卓客户端，手机抓海外源仍需手机开代理，且电脑和手机数据完全不互通，后续改信源要维护两套代码 |
