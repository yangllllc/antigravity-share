**先说核心结论**：**不用担心，旧版 SakuraCat 设置丢失后，你的同济双核 MCP（Antigravity + Codex/ChatGPT 共用）和 DeepSeek Harness (DSH) 底层直连穿透目前在实测中全部正常可用；而且“TUN 模式”其实并没有消失，新版里的“增强模式”就是它。**

### 一、 现状核查与原理解析（含新版 SakuraCat 2.4.6 变化）

1. **为什么 TUN 模式不见了？“增强模式”可行吗？**
   - **内核换代改名**：旧版 SakuraCat `1.6.2` 是 Clash Meta（虚拟网卡 `Meta`，Fake-IP `198.18.0.1`）；你刚重装的 **`2.4.6`** 底层已重写为 **`sing-box`** 内核，**“增强模式”本质上就是旧版的 TUN 模式**。
   - **实测证据**：当前系统已生成虚拟网卡 `tun0 (172.19.0.1/30)`，且默认路由 `0.0.0.0/0 -> 172.19.0.2 (metric 0)` 已生效，同时系统代理指向 `http://127.0.0.1:12450`，当前代理模式为 **`global`（全局模式，节点：`日本优选`）**。
   - **结论**：**增强模式完全可行**，对 Antigravity / Codex 这类部分子进程不吃 Windows 系统代理的工具反而更稳。

2. **为什么重装清空了 SakuraCat 设置，MCP 和 DSH 却依然能用？**
   - 核查历史对话（`bab10e4d` 与本会话），当初因为旧版 SakuraCat 每次重启都会用订阅覆写规则，我们早把穿透逻辑下沉到了 **OS 物理网卡绑定层**（强制从校园网物理网卡 `WLAN: 100.73.220.134` 直发同济内网 `10.67.0.251/252` 与国内直连 IP），**完全不依赖 SakuraCat 内部规则**。

### 三、 发现的 2 个潜在隐患（及你只需手动调 1 处的建议）

1. **当前开着“全局模式（`global`）+ 系统代理 `127.0.0.1:12450`”的副作用**：
   - 虽然 **MCP 脚本** 与 **DSH Node 后端** 的 socket 穿透已经绕开了 `tun0`，但 **Chrome/Edge 浏览器** 以及 **DSH 桌面前端界面（Electron 渲染层如果读取系统代理 `127.0.0.1:12450`，目前未启动 DSH 实测，属未验证风险）** 一旦走 `127.0.0.1:12450` 访问 `agi.tongji.edu.cn` 或 `platform.deepseek.com`，仍会撞上实测到的 **HTTP 403**。
   - **建议操作（二选一）**：
     - **推荐**：在 SakuraCat 2.4.6 首页把 **全局模式** 切回 **规则模式（智能分流）**——我查到它的数据目录已内置 `geosite-cn.srs` 和 `geoip-cn.srs`，切到规则模式后国内/校内站点自动直连，Antigravity 与海外服务照常走代理。
     - **若必须保持全局模式**：在 SakuraCat 2.4.6 右下角 **设置 → 进阶选项 → 路由规则** 中，将 `agi.tongji.edu.cn`、`tongji.edu.cn`、`platform.deepseek.com`、`api.deepseek.com` 加入 **直连（DIRECT）** 即可（新版 `config.json` 已加密，需在客户端 UI 里添加，不能直接改明文文件）。
2. **网卡黑名单防御补齐（可选加固）**：
   - 目前 `tongji_deepseek_mcp.ps1` 与 DSH 补丁 `index.js` 靠白名单（`WLAN|Wi-Fi|以太网|Ethernet`）天然排除了新版 `tun0 (172.19.0.1)`，暂时没受影响；但显式把 `tun\d*`、`172.19.` 加入黑名单，并在 DSH 补丁中追加 `NO_PROXY` 白名单会更防未来改名冲突。
