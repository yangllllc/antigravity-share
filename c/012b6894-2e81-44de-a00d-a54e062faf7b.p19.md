## 一、这次到底修改了什么？为什么要改？原理是什么？

本轮一共动了 **3 个底层工程安全机制** + **2 条常驻规则措辞**：

### 1. 工程修复一：批复绑死不可变版本（修“批复错版”与“水位误推”）
- **旧版问题**：同一轮整理如果先生成了 V1（比如 `OP-001` 写着“双栏”），后来改稿重新 `stage` 成 V2（`OP-001` 变成“单栏”），你手里拿着旧审阅页点了“同意 OP-001”，旧程序只认编号 `OP-001`，结果把你根本没看过的“单栏”落盘了。另外，如果批复漏写了一项，旧程序会直接当成“你驳回了”写进负反馈；一个长对话拆成两批时，只审完第一批就提前把整个对话标记为“已读完”。
- **修改原理（内容寻址 + 显式完备校验 + 批次门控）**：
  - 就像签合同要盖**骑缝章**：每次 `stage` 把你实际看到的全部提案内容 + 对应抽取清单算一个唯一 SHA-256 指纹 `plan_hash`，冻结存进 `plans/<hash>/`；在线网页、离线导出的 `decisions.json` 和聊天批复**全部必须带上这枚 `plan_hash`**，核对不一致直接拒收。
  - 批复列表必须与提案 `op_id` 严丝合缝（缺项保持待审、不记驳回；重复提交同一份批复直接返回原收据，幂等不重做）。
  - 新增 `batch_progress.json`，只有某个对话的**所有分片**都审完（哪怕明确零候选）才推进它的水位。

### 2. 工程修复二：精准撤回补齐连带状态与冲突锁（修“revert 误删”）
- **旧版问题**：如果“规则 A”被你批准的“规则 B”替代了（A 自动变成 `superseded`），后来你又批准修改了 B 的内容，再拿第一次的收据去撤回“新增 B”——旧程序**只看条目 ID 不看现状**，直接把新版 B 删掉，而且忘了把 A 恢复成 `active`，导致新旧两条全没了。
- **修改原理（乐观并发控制 / CAS + 全组原子逆转）**：
  - 每次 `apply` 写收据时，不只记主条目 B，而是把**连带改动的 A** 的“改前/改后完整快照”一起记入 `affected_entries`。
  - 撤回前在锁内做一次“验货”：把磁盘上 A 和 B 的**当前状态**与收据里的“改后状态”逐字段比对。只要其中任何一条被人动过，就**整组报错退出、零改动、零负反馈**；全部吻合才把 B 删掉并把 A 原样恢复成 `active`，同时给收据打上 `reverted: true` 防止重复撤回。

### 3. 工程修复三：快照存在性清单 + 崩溃恢复日志（修“回滚不完整”）
- **旧版问题**：
  1. 首次运行前还没有 `watermark.json`，旧快照清单里压根没登记它，所以回滚并要求重置水位时，新生成的 `watermark.json` 删不掉；
  2. 恢复快照时如果某个备份文件丢了或损坏了，旧代码静默跳过，导致“一半恢复一半没恢复”；
  3. 旧代码只靠 Python 的 `try/except` 回滚——万一写到一半进程被系统强杀或断电，`except` 根本来不及执行，下次启动也不会清理烂摊子，而且旧文件锁会卡死 10 分钟。
- **修改原理（预检 + 预写事务日志 WAL 思想 + OS 内核锁）**：
  - 快照 v2 像“房屋交接清单”：不论文件原本在不在，全部受管目标都登记 `exists: true/false` 和 SHA-256；回滚前先**一次性全检**所有备份文件和哈希，哪怕错 1 个字节都在动盘前报错，确保不会改坏一半；原本不存在的文件按清单直接删除还原。
  - 改盘前先落盘一张 `pending_tx.json`（记下快照 ID 和收据前像），等所有文件及收据都安全落盘才撕掉这张纸条。一旦中途被强杀，下次运行任何正常命令（如 `status`）看到纸条还在，就会自动按快照把系统拉回提交前的一致状态。同时把进程锁换成 Windows 内核级文件锁（`msvcrt.locking`），进程一死操作系统秒释放锁，不留僵尸锁。

### 4. 规则微调：收窄 `RULE-001` 与 `RULE-002` 的触发面
- **为什么改**：旧版 `RULE-001` 写“执行……或脚本前”，会误伤不需要 Python/FFmpeg/Node 的普通脚本，也会在项目自带虚拟环境时强行跳去用机器级路径；旧版 `RULE-002` 把你的“研一身份”和宽泛的“工程概念”常驻进每一轮对话，哪怕你只是修一个软件 Bug，模型也容易忍不住进入“教学辅导 + 出练习题”模式。
- **怎么改**：Tier 1 只保留**极窄、精准的触发闸门**（真缺运行环境才查环境档；真在辅导或需要判断知识起点时才读学习记录并严分三态），把具体路径、身份、光学平台直觉和练习节奏全部留在 Tier 3 按需读取——信息一字未丢，但干扰降到最低。

## 二、这样修改后有什么好处？

1. **授权可信**：你看到的 Diff 就是落盘的精确内容，再也不会出现“审 A 落 B”或漏审被误当驳回。
2. **反悔真正安全**：撤回“替代关系”不会留下僵尸条目，也不会误杀你后来辛苦改好的新版本；真遇到崩溃/强杀，重启即自愈。
3. **日常对话更清爽**：纯工程/排错任务不再被光学学习规则分心或强塞练习题，同时辅导学习时依然保留全部三态边界保护。
