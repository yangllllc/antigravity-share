### 一、为什么连接校园网开启 SakuraCat 后，`DeepSeek Harness` 无法使用同济 API（关掉 VPN 才可用）？

#### 1. 根本原因分析
通过排查 `DeepSeek Harness` 的运行日志与同济大学 `agi.tongji.edu.cn` 的网络拓扑，定位到两层拦截机制：
1. **同济 API 网关的「内外网双视图 DNS（Split-Horizon DNS）」与内网源 IP 校验**：
   - 在校园网内使用同济 DNS（`202.120.190.208`）解析 `agi.tongji.edu.cn` 时，返回的是**同济校内私网 IP**（`10.67.0.251` / `10.67.0.252`），只有通过校园物理网卡直连该内网地址才能正常调用。
   - 当开启 SakuraCat（尤其是开启 `TUN 虚拟网卡 Meta` + `Global 全局模式`）时，`DeepSeek Harness`（底层基于 Electron / Node.js）发出的请求会被 `Meta` 虚拟网卡劫持，并通过香港代理节点（`using GLOBAL`）或公网 DoH（`dns.alidns.com`）出站，导致同济网关识别为校外公网访问，直接拦截并返回 `403 当前网络环境不支持` 或连接超时。
2. **SakuraCat 客户端每次重连都会覆写内核配置**：
   - SakuraCat 每次开启或切换节点时，都会用默认模板覆盖 `config.yaml`，且如果将 SakuraCat 切为 `Rule`（规则模式），其内置的 `GEOIP, CN, DIRECT` 规则缺少 `no-resolve` 标记，会导致访问 `chatgpt.com` 时先向被污染的国内 DNS 发起解析并卡死超时（`i/o timeout`）。

#### 2. 已为您实施的永久修复方案
为了同时保证 **「海外访问（ChatGPT 等）零超时」** 与 **「同济校园网 API 100% 直连免 403」**：
- **`DeepSeek Harness` 底层注入物理网卡直连穿透钩子（无需关 VPN）**：
  - 在 `DeepSeek Harness` 启动必加载的插件入口 `index.js` 顶部注入了 Node.js 网络层 Hook：
    1. 拦截 `dns.lookup`：当目标域名为 `agi.tongji.edu.cn` 时，直接强制映射至同济校内网网关 `10.67.0.251`；
    2. 拦截 `net.Socket.prototype.connect`：当连接目标为 `10.67.0.251` / `10.67.0.252` 时，自动枚举本机物理校园网网卡（`WLAN` / `以太网`，如 `100.78.x.x`）并强制绑定 `options.localAddress`，直接在 Socket 层绕过 SakuraCat 的 `Meta` 虚拟网卡。
- **在 `DeepSeek Harness` 中新增 `Kimi-K3.1-Pro` 模型**：
  - 已更新配置文件 `cordis.patch.yml`，在 `tongji` 供应商下新增了 **`Kimi K3.1 Pro (校园免费)`**（模型 ID：`Kimi-K3.1-Pro`），重启 `DeepSeek Harness` 后即可在模型下拉列表中直接切换使用。
- **SakuraCat 与 SDKDNS 配置同步优化**：
  - `vortex.json`：保持 `global` 模式以确保 `chatgpt.com` 秒开不超时；
  - `adv.json`：已为 SDKDNS 配置 `agi.tongji.edu.cn`、`tongji.edu.cn`、`edu.cn` 最高优先级 `DIRECT` 直连规则。
