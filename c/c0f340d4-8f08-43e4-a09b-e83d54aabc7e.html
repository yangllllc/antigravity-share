二、为什么压缩成 .rar 无法上传？（不止是格式问题）

我检查了你电脑上刚刚生成的 share-conversation.rar，除了格式原因外，其实同时踩了 3 个坑：

  • 格式原因（最直接）：

Web 端与云端智能体后台（包括 DSH 本身内置的压缩库如 fflate/pako 和常规 Python/Node 后端）几乎只支持标准 .zip，不支持专有闭源的 .rar 格式。服务器收到 .rar 后要么在前端白名单就被拦截，要么后端无法解压。

  • 你打包的 share-conversation 本身无法在云端运行（更隐蔽的坑）：

查看 share-conversation/SKILL.md 可知，它写死了你电脑上的本地路径 C:\Users\Administrator\.gemini\config\plugins\antigravity-share-hub\server.ps1 和 http://localhost:5210/。云端容器根本连不到你本机，即使改成 .zip 上传也没有用。

  • 两个隐藏的 .zip 打包规范坑：
  • 结构与路径斜杠坑：DSH 的技能扫描器只扫一层目录（<root>/<skill-name>/SKILL.md），且目录名必须与 SKILL.md frontmatter 里的 name: 一致；此外 Windows 自带的 Compress-Archive 有时会写入反斜杠 \ 导致 Linux 云端解压出错。本次我已改用 Python zipfile 全部生成标准 POSIX 正斜杠 / 路径的 .zip。
  • 体积超限与本机配置污染坑：例如完整的 ppt-master 有 13,018 个文件 / 37.6 MB（压缩后仍达 20.88 MB，其中仅 templates/sounds/ 音频和 templates/icons/ 1.2 万个小图标就占了约 21.8 MB），极易触发云端单包体积/文件数限制；而 course-ppt-lab 里的 references/local-environment.md 写死了你本机的 C:\Users\... 路径和 KWPP.Application，传到云端会误导模型。
