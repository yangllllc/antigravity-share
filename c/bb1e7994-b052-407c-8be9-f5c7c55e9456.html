一、 为什么 Antigravity 没有像 Gemini/Codex 那样的分享按钮？

  • 运行机制不同：
  • Gemini / Codex Web 版：是纯云端 SaaS 应用，所有聊天记录都保存在云端服务器，点击分享只是生成一个指向云端快照的公共网页链接。
  • Antigravity：是本地原生开发者工作台 / IDE 桌面应用。它深度绑定你的本地环境，能够直接读写本地磁盘文件、运行系统终端命令。
  • 隐私与代码安全考量：
  • 对话中通常包含你的本地项目源码、绝对路径、终端输出甚至密钥配置。为了防止敏感代码与本地信息意外泄露，Antigravity 默认采用严格的本地隔离策略，不会自动将对话上传生成公开外链。

  • Antigravity 插件市场（Agent Plugins / Skills）：

  • IDE 扩展市场（VS Code / Open VSX）：

如果你使用的是 Antigravity IDE（VS Code 架构版本），社区中有一款名为 Antigravity History - Browse & Export AI Chat（插件 ID：neo1027144.antigravity-history）的扩展工具，支持在状态栏通过 AG History 面板一键浏览本地所有对话轨迹，并批量或单条导出为 Markdown (.md) 或 JSON 文件。

  • 操作系统级沙箱回收机制（Job Object）：

在 Antigravity 中，Agent 执行的所有命令行操作都会被放入 Windows 的 Job Object（沙箱作业对象） 中。

  • 连接被切断的时序悖论：

当 Agent 在后台拉起 HTTP 服务时，服务确实短暂启动成功了；但是，一旦 Agent 完成当次发言并交还控制权给你时，操作系统内核会触发 JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE，瞬间强制杀死该沙箱内的所有子进程（包括 5210 端口服务）！

  • 结果：在你看到回复并伸手去点击 http://localhost:5210/... 的那一毫秒，后台服务早已经被操作系统强制终止了，因此你的浏览器必定报 ERR_CONNECTION_REFUSED（无法连接）。
