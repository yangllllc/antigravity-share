### 2. 审计 #9 / #12 修复设计与 TDD 方案

#### 2.1 审计 #9（负反馈 ID 复用误拦、无序指纹失真、审阅对比与锁内重查）

**核心矛盾**：当前 `governance.py` 将无作用域裸 `entry_id` 设为硬拦条件、用 `sorted(set)` 丢弃词序与否定极性，且 `apply_decisions` 未在 `ProcessLock` 内重查最新账本。

**拟定最小改动（涉及 `governance.py`、`review_ui.py`）**：
1. **永久单调 ID + 移除裸 `entry_id` 一票否决**：
   - 删除 `check_feedback_collision` 中 `blocked_entry_id` 分支（旧账本 `entry_id` 仅作历史溯源，不封禁未来新项）。
   - `_next_entry_id(prefix, used_ids)` 改为取匹配 `^{prefix}-(\d+)$` 的 `max + 1`（不再填空洞）；`stage_proposal` 的 `used_ids` 合并同 `(tier, topic)` 下现存条目 + 历史账本记录 + 同批已分配 ID，确保已拒/已撤编号不再复分配。
   - *放弃的方案*：新建 `state/id_counters.json` 独立计数器——需新增受管目标接入快照 v2 与事务清单，增加复杂度而收益有限。
2. **v2 保序精确指纹（保留词序、否定、适用范围）**：
   - `normalize_text_ordered(text)` 做 NFKC 规范化、小写化、标点转单空格、折叠空白（保留全部单字如 `不/勿/非/仅` 及英文短词 `no/not` 与词序）。
   - 同时校验整条指纹 `v2|{tier}|{topic}|{norm_title}|{norm_claim}` 与非空主张指纹 `v2c|{tier}|{topic}|{norm_claim}`（防止仅改标题绕过精确禁止）。
   - 兼容旧账本：比对旧记录时优先基于其保留的 `title`/`claim` 现场重算 v2 指纹，避免旧词袋指纹把反序新提案误判为 `exact_fingerprint`。
   - `banned_keyword` 默认限定同作用域（除非账本记录显式 `global_ban: true`）。
3. **近似命中（`semantic_token_overlap`）降误报 + 审阅页并列展示**：
   - 增加显式禁止/肯定极性检测（如一方含 `禁止/严禁/禁用/不要/勿/不得/forbid/never/disable/not` 而另一方不含，不按同义重复拦截，避免“禁用 X”误杀“使用 X 时加参数 Y”）；收紧短集合门槛为 `jaccard >= 0.50 or (min_sz >= 6 and overlap >= 0.70 and jaccard >= 0.35)`（已核验 `test_dream_e2e.py` 的 `test_03` 同义改写案例 `jaccard=0.517, overlap=0.682` 仍稳命中）。
   - `feedback_match` 扩展携带 `severity`（`"hard"` vs `"advisory"`）、`matched_title`、`matched_claim`、`matched_type`、`matched_at`；在 `review_ui.py` 与 `review_summary.md` 中**并列展示旧主张、历史理由与本次新主张**。
