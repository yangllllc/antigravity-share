### Git 历史洗净（单提交重建 + 强推）优缺点分析

#### 优点
1. **消除公开提交历史中的旧敏感快照**：目前网页本身已经看不到 `eb9e76bb`（个人异地恋/地理）、`a0ca09c2`（今日组会）、16 条内部子代理日志及旧版未脱敏的 `C:\Users\<USER>\` 路径，但任何人在 GitHub 仓库的 `Commits` 历史里仍可点开过去 230 条旧提交看到原全文。洗净后，公开分支历史上只剩 1 条干净基线提交，普通访客浏览历史或 `git clone` 都再也看不到旧内容。
   - *诚实边界*：GitHub 服务端对被强推替换掉的孤立旧 commit 对象会在后台周期性 GC 后才物理回收；若无人提前保存过旧 commit SHA 直链，实际上已不可见。
2. **仓库与 `.git` 体积骤降 ~90%**：目前 `.git` 占 **`22.26 MB`**（大头是过去 230 次提交与反复改写的 324 个 `.p*.md` 历史对象）。洗净后本地 `.git` 与远端仓库都会压回约 **`1–2 MB`**，后续 `git push` 与 GitHub Actions `Checkout` 更快、更不易遇网络超时。
3. **对日常使用零破坏**：所有保留对话的公网直链、桌面快捷方式、`.md` 下载按钮以及后续 `Stop` Hook 自动同步全部 **100% 原样继续工作**。

1. **丢失过去 13 天的“逐轮 Git Diff 时光机”**：之后无法在 GitHub 上用 `git log` 查看“某条对话几天前某轮长什么样”（但每条对话页面里本身就有完整 1~N 轮全文，且本机 Antigravity 客户端的 `brain/` 原始日志完好无损，这个历史 diff 几乎没有实际用途）。
2. **多机 `git pull` 冲突（仅限其他电脑克隆过该仓库的情况）**：如果你在别的电脑手动 `git clone` 过 `antigravity-share`，那台机器下次 `git pull` 会提示分叉，需要重新 `clone` 或 `reset --hard origin/main`。但目前这个仓库仅由你本机 `site/` 单向自动推送，基本无此影响。
