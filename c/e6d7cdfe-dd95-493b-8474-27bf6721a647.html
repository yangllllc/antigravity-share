Antigravity Assistant

已定位浅色主题下看不清的根因，并对整个插件做了一轮前后端深度审计与全面修复（已升级至 v1.1.0）。

一、浅色模式看不清的根因（已彻底修复）

  • 根因（实测）：Antigravity 的 preload.js 会在加载时通过内联样式将 body 背景切为宿主变量 var(--background)（浅色模式下变白），同时通过 theme-change 消息把宿主配色变量写入 :root。但旧版 styles.css 全部硬编码了深色模式专属浅色字（#eef2ff、#cbd5e1、#93c5fd、#fde68a、#6ee7b7 等），app.js 中还有一处内联浅绿色字体，导致切换浅色主题后变成“白底浅字 / 深黑弹窗浮在白底上”。
  • 修复方式：
  • 对齐官方 swarm_board 宿主变量机制：styles.css 全面改由宿主变量驱动（--background / --card / --foreground / --muted-foreground / --border / --primary / --primary-foreground），并为浅色模式（:root）与深色模式（:root[data-theme="dark"]）分别配置高对比度的语义状态色、弹窗、胶囊标签、下拉选项和滚动条。
  • 实时双层主题同步：app.js 优先监听 Antigravity 宿主发出的 theme-change 中的 themeType（实查主程序为 light / hcLight / dark / hcDark），并用 MutationObserver + 1×1 canvas 亮度采样兼容任意 CSS 色域（含 oklch / color(srgb ...)）及独立浏览器回退。
  • 禁止旧样式缓存：main.mjs 为 /、/styles.css、/app.js 和 /api/* 统一加上 Cache-Control: no-store, no-cache, must-revalidate，避免 WebView 残留旧 CSS。

二、顺带排查并修复的插件不足

1. 后端数据一致性与协议 Bug（store.mjs）

  • .pbtxt 解析与修改防误伤：旧正则会误匹配标题字符串或嵌套块里的 archived:true（比如标题含该词会被改坏）。已改写为顶层词法扫描器 scanPbtxtTopLevelFields，跳过双引号字符串与嵌套 {...}；同时在 .pbtxt 缺省 archived: 字段时正确回退读取 SQLite FTS 状态。
  • 修复 UpdateProject RPC 请求结构错误：实查 Antigravity 主程序 language_server.exe 发现 UpdateProject 要求 { project: updatedProject } 包装而非扁平对象；旧代码会导致归档/恢复项目时 RPC 静默失败而退回写本地文件。现已修正为实时 RPC 生效。
  • 回收站还原防 FTS5 索引重复：restoreTrashItem 在单事务内先 DELETE FROM conversations_fts WHERE conversation_id = ? 再插入快照，杜绝重复索引行；并回传 wasArchived，若还原的原本是已归档对话，前端会明确提示前往「已归档对话」查看。
  • 删除对话清理残留与并发容错：通过 DeleteCascadeTrajectory 删除后若 Antigravity 遗留孤立 .pbtxt 则自动清理，避免越删越多“孤立残留”；文件删除加入 Windows 占用重试（EPERM/EACCES/EBUSY）；只读 SQLite 连接同样开启 PRAGMA busy_timeout = 5000，避免主进程写库时刷新面板触发 SQLITE_BUSY。

2. 侧栏交互与窄屏体验补齐（index.html & app.js）

  • 窄屏 Aux Pane 响应式布局：宽度 ≤ 640px 时卡片自动转为纵向排版（标题占满整行、操作按钮在底部分隔栏换行排列），不再把中文标题挤成竖排两三个字。
