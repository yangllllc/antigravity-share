### 二、`agy-capsule` 的用处与底栏胶囊实现原理

根据 `README.md` 与源码，这个插件由两套机制组成：

1. **主要用途**
   - 在输入框底栏模型按钮旁提供紧凑悬浮胶囊，实时查看 **上下文占用/明细/缓存过期提醒**、**生成速度与首字等待提醒**、**多模型 5h/周剩余额度与重置倒计时**、**请求报错原因诊断**，以及可选的**优化模型与思考强度选择器**（你当前在 `settings.json` 里也已开启 `modelEffortPicker: true`）。
2. **为什么侧栏能用、底栏胶囊却必须依赖 CDP 参数**
   - **侧栏（Sidecar）**：走 Antigravity 官方插件协议（当前运行在 `127.0.0.1:50061`），通过本地 Language Server 读取会话和配额数据，不依赖调试端口。
   - **底栏胶囊（CDP 注入，见 `deck_injector.mjs`）**：Antigravity 2.0 官方插件接口只开放了右侧 Aux Pane 侧栏，不提供输入框底栏（`.agy-composer-footer`）的原生 UI 挂载点。因此底栏胶囊必须走一条 4 步链路：
     1. 启动 `Antigravity.exe` 时带上 Electron 参数 `--remote-debugging-port=0` → Chromium 在 `127.0.0.1` 随机绑定本地调试端口，并把端口号写入 `%APPDATA%\Antigravity\DevToolsActivePort`；
     2. 插件 sidecar 读取 `DevToolsActivePort`，向 `http://127.0.0.1:<port>/json/list` 查询页面列表；
     3. 对照 `daemon/hub_*.json` 核验当前会话的 composer 页面源（已确认本机 `hub_50031.json` 正常，且插件明确适配当前安装的 `Antigravity 2.33.0`）；
     4. 通过本机 CDP WebSocket 调用 `Runtime.evaluate`，在 `.agy-composer-footer > div:first-child` 注入隔离的 Shadow DOM 胶囊条（`#agy-capsule-host`）。

### 核心矛盾与暂缓直接覆盖的原因

**核心矛盾**：你当前正在靠 `1.6.2` 联网，但 `1.6.2`（Electron / NSIS）与 `2.4.6`（Inno Setup）属于**跨代不同安装框架**——直接覆盖会留下旧版垃圾与服务冲突，而卸载旧版会立刻中断外网（含当前会话与模型的连接）。

动手前定位到 3 个必须规避的失效机制：
1. **不能直接硬覆盖**：Inno Setup 安装器无法自动卸载旧版 NSIS（卸载 GUID 不同），直接覆写进 `D:\sakuracat` 会导致 414 MB 的旧版 Electron/Chromium 文件、`Uninstall SakuraCat.exe` 及后台服务 `com.vortex.helper` 全部残留，并产生两个卸载项与潜在代理/TUN 冲突。
2. **不能直接强杀进程**：当前系统代理 `HKCU\...\Internet Settings\ProxyEnable = 1`（`127.0.0.1:7897`）。若强杀 `SakuraCat.exe` 而不清除系统代理，连国内直连及新版 `2.4.6` 登录接口都会无法访问（官网教程也专门提醒了这一点）。
3. **装完无法自动恢复联网**：官网教程明确说明 `2.4.6` 安装后需用注册邮箱/密码重新登录，并手动开启主页的 **系统代理** 开关才会恢复联网（首次启动还会弹出 Windows 防火墙授权提示，需点“允许”）。
