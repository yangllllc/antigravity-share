核心矛盾与暂缓直接覆盖的原因

核心矛盾：你当前正在靠 1.6.2 联网，但 1.6.2（Electron / NSIS）与 2.4.6（Inno Setup）属于跨代不同安装框架——直接覆盖会留下旧版垃圾与服务冲突，而卸载旧版会立刻中断外网（含当前会话与模型的连接）。

动手前定位到 3 个必须规避的失效机制：

  • 不能直接硬覆盖：Inno Setup 安装器无法自动卸载旧版 NSIS（卸载 GUID 不同），直接覆写进 D:\sakuracat 会导致 414 MB 的旧版 Electron/Chromium 文件、Uninstall SakuraCat.exe 及后台服务 com.vortex.helper 全部残留，并产生两个卸载项与潜在代理/TUN 冲突。

根据 README.md 与源码，这个插件由两套机制组成：

  • 主要用途

  • 侧栏（Sidecar）：走 Antigravity 官方插件协议（当前运行在 127.0.0.1:50061），通过本地 Language Server 读取会话和配额数据，不依赖调试端口。
  • 底栏胶囊（CDP 注入，见 deck_injector.mjs）：Antigravity 2.0 官方插件接口只开放了右侧 Aux Pane 侧栏，不提供输入框底栏（.agy-composer-footer）的原生 UI 挂载点。因此底栏胶囊必须走一条 4 步链路：
  • 启动 Antigravity.exe 时带上 Electron 参数 --remote-debugging-port=0 → Chromium 在 127.0.0.1 随机绑定本地调试端口，并把端口号写入 %APPDATA%\Antigravity\DevToolsActivePort；
  • 插件 sidecar 读取 DevToolsActivePort，向 http://127.0.0.1:<port>/json/list 查询页面列表；
  • 对照 daemon/hub_*.json 核验当前会话的 composer 页面源（已确认本机 hub_50031.json 正常，且插件明确适配当前安装的 Antigravity 2.33.0）；
  • 通过本机 CDP WebSocket 调用 Runtime.evaluate，在 .agy-composer-footer > div:first-child 注入隔离的 Shadow DOM 胶囊条（#agy-capsule-host）。
