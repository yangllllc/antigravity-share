核心目标

我想把学校每周赠送且当前有大量富余的同济免费 API 额度（1000 积分/周，与我本机同济 MCP 共用同一密钥与周额度池），接入 AIRadar 作为优先的批量翻译/摘要通道；同时保证离校、校园网不可达、限流或额度到达自设上限时，能无缝、不卡顿地自动回退到现有的智谱 glm-4-flash，不破坏现有单文件 AIRadar.exe 打包与稳定运行。

必须严守的硬约束（逐条落进设计与验收）

  • 同济通道协议与模型约束：
  • 接口地址：https://agi.tongji.edu.cn/v1/chat/completions（标准 OpenAI 兼容格式，严禁走 /messages）。
  • 仅使用高吞吐模型 DeepSeek-V4.1-Flash（严禁把慢吞吐 Kimi-K3.1-Pro 用于批量翻译）。
  • 强制关闭思考：请求体必须同时传 chat_template_kwargs: { enable_thinking: false, thinking: false }（漏传 thinking: false 会导致 DeepSeek 返回空 content）。
  • 校园网直连穿透（极关键，否则必报 HTTP 403）：
  • 本机装有代理软件（SakuraCat tun0 / SDKDNS mihomo），Node 22 若走全局代理或公网 VIP（202.120.188.251）访问同济必报 403。
  • 同济请求必须使用独立的、仅限本次请求使用的 HTTP 客户端/dispatcher（例如 per-request undici.Agent 或独立 https.Agent，绝不走 HTTP_PROXY/HTTPS_PROXY/ALL_PROXY 或全局 ProxyAgent）：
  • 自定义 DNS lookup：强制轮询解析到校内内网 VIP 10.67.0.251 / 10.67.0.252；
  • 保留 TLS SNI 与证书校验：servername: 'agi.tongji.edu.cn'；
  • 绑定物理校园 IPv4 出口网卡（localAddress）：匹配 WLAN|Wi-Fi|以太网|Ethernet|本地连接，并显式黑名单排除 Meta|wintun|TAP|VPN|vEthernet|Loopback|sing-tun|mihomo|\btun\d*\b 以及 169.254.*、198.18.*、172.19.*、127.0.0.1。
  • 回退通道 glm-4-flash 严格隔离：
  • 原有 glm-4-flash 必须保持其独立的公网 Base URL、独立的 API Key 配置项与普通网络路由，绝对不可复用同济的 VIP lookup、物理网卡绑定或 servername: 'agi.tongji.edu.cn'。
  • 防卡死超时、快速回退与离校冷却：
  • 同济请求必须同时设连接超时（≤5s）与 总请求超时（AbortSignal，如 25–30s），避免 TLS 建连后响应挂死。
  • 遇 401/402/403/429/5xx、连接失败、超时或返回空 content 时，当次任务立刻透明回退到 glm-4-flash 完成，不影响入库与前端展示。
  • 遇 401/402/403 或物理网卡/内网 VIP 不可达（典型离校场景）时，启用进程内短冷却（例如 5–10 分钟内直接走 glm-4-flash，避免每条新闻白等 5 秒；支持手动刷新或冷却到期后自动重新探测）。
  • 与本机 MCP 共享周额度的防饿死闸门：
  • 同济通道并发数严格限制在 ≤2（避免冲击校内网关限流并撞车本机 MCP）。
  • 在 AIRadar 本地状态（如现有 SQLite）中增加一个可配置的同济日/周预算软上限（例如按请求数或 token 估算封顶，默认给本机 MCP 预留充足裕度，触顶后自动切回 glm-4-flash），并在状态接口/日志里可观测同济与智谱的命中与回退计数。
