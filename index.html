how can i change antigravity change usage language from English to Chinese

Antigravity Assistant

There are two separate settings here: the interface language and the language the AI agent replies in.

1. Interface language (menus, buttons, settings)

Antigravity IDE is built on VS Code, so you change the language the same way:

  • Press Ctrl+Shift+X to open Extensions.
  • Search for Chinese (Simplified) Language Pack and click Install. Use Chinese (Traditional) if you want that instead.
  • Press Ctrl+Shift+P and run Configure Display Language.
  • Choose 中文(简体) / zh-cn, then click Restart.
[!NOTE]
The language pack only translates the parts that come from VS Code. Antigravity's own panels, such as the Agent Manager, may still show some English. I couldn't find an official Antigravity language setting in the docs I have. Check https://antigravity.google/docs or the changelog to see if one has been added.

2. Agent reply language

To have me reply in Chinese, you can:

  • Ask in the chat: say "请用中文回复" or simply write to me in Chinese.
  • Make it permanent: add a global rule such as Always respond in Simplified Chinese. (请始终使用简体中文回复。) under Customizations → Rules. Rules docs: https://antigravity.google/docs/rules-workflows

我很好奇你的这个模型在对话过程中为什么会突然的中断，这个问题能否得到解决呢

Antigravity Assistant

我查了你电脑上的 Antigravity 日志（main.log），结论是：有一部分中断已经能确认原因，而且能解决；另一部分本地日志里看不到，只能先推测。

一、已确认：Antigravity 程序关掉或重启时，正在跑的任务会被打断

Agent 的后台服务（language server）跟着 Antigravity 程序一起运行。程序一退出，后台服务就关了，正在进行的回复、子任务和后台命令都会停掉。

  • 日志里每次中断都有 Shutting down language server… → Starting app 这两行，相隔几秒到几分钟。光 11 月 17、18 两天就有十几次。
  • 今天 09:50 那次是安装自动更新：日志里有 Install on explicit quitAndInstall，从 2.32.1 升到 2.32.2，程序重启了一次。10:06 又重启了一次。
  • 这次对话里，我在 11-07 和 11-18 两次收到了"服务器重启，所有子任务已停止"的系统通知，和日志里的重启记录对得上。
  • 日志里没有崩溃类的记录（crash、render-process-gone 都没有）。所以不是软件自己崩溃，而是程序正常退出（关窗口、点"重启更新"、关机或重启电脑）。
  • 日志里大量的 wsl.exe --list 报错，是因为你没装 WSL，和中断无关，可以不管。

怎么解决：

  • 让 Agent 跑任务时，不要关掉 Antigravity 主窗口。
  • 在 Settings → App Settings 里打开 Run in background（后台运行）和 Keep computer awake（保持电脑唤醒）。前者让关窗口时程序继续在后台跑，后者防止电脑睡眠打断任务。这两个选项是文档里写的，但具体名称以你的界面为准。
  • 弹出更新提示时，等手头任务结束再点重启安装。
  • 真被打断了，直接发"继续"就行，对话记录还在。之前派出去的子任务需要我重新唤起。

二、没法确认：网络或模型那边的问题

这一类中断的表现是回复写到一半停下，或者报个错，但程序本身没有重启。可能的原因有两个：

  • 代理断开：你的系统代理是 127.0.0.1:7897（看端口应该是 Clash Verge）。模型回复是靠一条持续很久的连接一点点传回来的，代理一旦换节点（比如开了"自动测速选择"或"负载均衡"策略组），或者节点本身断了，这条连接就会被切断。
  • 模型服务那边：比如高峰时段容量不够、触发限流，或者一次输出太长。

这两点我都没验证：后台服务的日志 language_server.log 是空的（0 字节），本地看不到模型请求的报错。可以先试试：任务期间把 Clash 固定在一个稳定的节点上，不要用自动切换的策略组。

下次中断时，怎么判断是哪一类

记下中断的时间，然后在 PowerShell 里运行：

Select-String "$env:APPDATA\Antigravity\logs\main.log" -Pattern "Shutting down language server|Starting app" | Select-Object -Last 5
  • 中断时间附近有这两行 → 是第一类，程序重启了。
  • 没有 → 多半是第二类，去 Clash 的连接日志里找同一时间有没有连接断开的记录。

想跟你确认两点

  • 你遇到的中断是哪种？是回复写到一半停住或报错，还是整个界面闪一下、重新加载？前者更像网络问题，后者就是程序重启。
  • 是不是长任务（跑十几分钟以上）或者长回复时更容易断？如果是，代理断开或输出太长的嫌疑会更大。

另外更正一下上一轮的话：我当时说桌面版"暂未开放中文界面选项"，其实没有核实过，你可以在 Settings 里再找找有没有语言选项。
