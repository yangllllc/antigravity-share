2. 核心架构选型、权衡与红队加固

本次核心矛盾在于：既要让强模型自由做跨会话语义归并、冲突覆写与边界判断，又要防止大输出触发约 60 秒网关断连、防止记忆膨胀撑爆常驻上下文、防止错误规则静默生效或反复回流。

  • 增量读取与水位线（extractor.py、redact.py）
  • 选型：隔离临时目录拷贝 SQLite（含 -wal/-shm）+ PRAGMA quick_check 重试后只读打开；按 conversation_id 独立维护 {last_step_index, anchor_step_hash, compact_sig, full_sig} 水位线；老对话续写自动附带前 1 轮 [CONTEXT_ONLY] 上下文，若文件截断或锚点行 SHA-256 漂移则自动全量重放。4 层防自污染（过滤 nesting_depth>0 子代理、哨兵标记与 /dream 识别、--exclude-cid、turn 级切片过滤）+ 13 类正则凭据脱敏 + 剥离 GENERIC 大输出 + 超长会话按轮次切分保证每批 ≤ 18,000 字符。
  • 否决：单一全局时间戳水位线（无法正确处理老对话续写）；直接只读打开 live SQLite（存在 Windows 锁冲突风险）；逆向 Protobuf（高脆弱且多余）。
  • 原生形态与三层 SSOT（store.py、plugin.json、SKILL.md）
  • 选型：Antigravity 原生 Plugin 结构（一键启停、与原生全局规则物理隔离）。Tier 0（用户 config/rules/*.md 与 CONTEXT_*.md）代码级路径硬锁禁止触碰（config_io.py）；Tier 1（promoted_rules.md）与 Tier 3（topics/<slug>.md，单文件 ≤ 150 行）为单一事实源（SSOT）；Tier 2 索引（INDEX.md）和常驻规则产物 AGENTS.md 100% 由脚本确定性编译，同时受 ≤ 140 行且 ≤ 12,000 UTF-8 字节约束（按行边界字节安全截断，杜绝截断中文多字节字符，溢出项自动降级为 topics/ 目录指针）。
  • 否决：自定义 MCP Server（常驻开销与全会话 schema token 税）；手写维护双份索引/规则文件（必然漂移）。
  • 分析编排与防超时（SKILL.md）
  • 选型：脚本承担全部确定性 I/O、清洗、校验、Diff、快照与原子写盘；模型只输出紧凑结构化 proposal.json（避免整文件重写触发 60 秒断连）。自适应路由：batches <= 2 主模型直出，batches > 2 按每 2 批派发原生只读 research subagent（Model="inherit"）抽取后再由主模型统一去重和冲突裁决，零外部 API/MCP。
  • 否决：每次强制拉起 Swarm/多代理（小增量浪费配额）；模型直接手写全量 Markdown/HTML。
  • 人工审阅、原子写盘与负反馈闭环（governance.py、review_ui.py）
  • 选型：三通道统一 decisions.json 契约——review-serve 加固本地服务（仅绑 127.0.0.1:0、校验 Host/Origin 防 DNS rebinding、256-bit CSRF nonce 一键应用）+ 离线双击 review.html 导出 JSON + 聊天内直接批复。写盘前必检 base_hash 漂移、加 PID 进程锁、生成只读（0o444）时间戳全量快照，同目录临时文件 flush+fsync+os.replace 重试，异常自动回滚。
  • 精准 Revert 与防改写绕过：revert 按条目 ID（MEM-XXXX/RULE-XXXX）精准撤回，保留人工后续手工注释且不盲目回退水位线；驳回/撤回同时沉淀到 feedback_ledger.jsonl，在后续提示词层和 stage 校验层（指纹 + 中英文 bigram 词袋重合度）双重阻断同义改写绕过。
  • 否决：纯 Git Diff 手工改（难结构化沉淀驳回理由）；无校验裸开 localhost 服务。
  • 触发策略
  • 选型：默认手动 /dream；内置纯只读 check-due 子命令，生产启用后按需可选挂接轻量 SessionStart 提醒或 Antigravity 原生 builtin: schedule 定时预处理，永不静默改写 Tier 1。
  • 否决：Stop Hook 每轮同步阻塞触发。
